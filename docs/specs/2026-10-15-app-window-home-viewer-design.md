# StepCap — หน้าต่างโปรแกรมเอง, หน้าหลักแบบ Scribe, โหมดดู/แก้ไข

สถานะ: ผู้ใช้อนุมัติแล้ว (2026-10-15) · ครอบคลุม "ส่วนที่ 0" และ "ส่วนที่ 1" จากทั้งหมด 6 ส่วน

## 1. ที่มาและเหตุผล

StepCap คือโปรแกรมบันทึกขั้นตอนการทำงานบน Windows สำหรับใช้คนเดียว ทำงานคล้าย Scribe ตอนนี้บันทึกได้จริงแล้ว
ผู้ใช้ทดสอบแล้วคลิกได้ขั้นตอนแบบ `คลิกปุ่ม "Start" ใน explorer` แต่ยังมีปัญหา 3 เรื่อง:

1. หน้าจอของ StepCap เปิดใน **Edge ซึ่งเป็นอีกโปรแกรมหนึ่ง** ผู้ใช้รู้สึกว่าโปรแกรม "เด้งไปเบราว์เซอร์" ผู้ใช้ต้องการให้ทุกอย่างอยู่ในหน้าต่างของโปรแกรมเอง
2. หน้าแรกยังเป็นแค่แผงควบคุมกับรายการคู่มือ ผู้ใช้ต้องการให้เหมือน **หน้า Home ของ Scribe** (ส่งภาพตัวอย่างมาให้ดู) โดยใช้**ธีมสว่าง**
3. หน้า "ดูตัวอย่าง" ซูมภาพเข้าหาจุดคลิก ผู้ใช้ต้องการให้**แสดงภาพเต็มจอ** และต้องการ**เมนู Edit แบบ Scribe** ซึ่งมีปุ่ม Edit/Done และแถบเครื่องมือลอยทางขวา

ผู้ใช้เลือกฟีเจอร์ระดับ Pro ของ Scribe ที่ไม่ใช้ AI มาทำทั้งหมด แบ่งเป็น 6 ส่วน ทำทีละส่วน:

| ส่วน | เนื้อหา | อยู่ในเอกสารนี้ไหม |
|---|---|---|
| 0 | หน้าต่างโปรแกรมเอง + หน้าหลักแบบ Scribe | ✅ |
| 1 | โหมดดู/แก้ไข + แถบเครื่องมือ (สีวงทั้งคู่มือ, สารบัญ, จำนวนขั้นตอน, วันที่, Linear/Grid) | ✅ |
| 2 | ตัวแก้ไขภาพ: รูปทรงวง, วาดลูกศร/กรอบ/ข้อความ, เบลอ/ปิดดำ, เปลี่ยน/เพิ่มภาพ/GIF, ดาวน์โหลดภาพ | ❌ ทำทีหลัง |
| 3 | ซ่อนข้อมูลอัตโนมัติ (ใช้รูปแบบตัวอักษร ไม่ใช้ AI) | ❌ ทำทีหลัง |
| 4 | ส่งออก PDF / Markdown / Word | ❌ ทำทีหลัง |
| 5 | Pages (รวมหลายคู่มือเป็นเอกสารเดียว) | ❌ ทำทีหลัง |

## 2. สิ่งที่มีอยู่แล้ว

โฟลเดอร์ `D:\dev\stepcap\` ใช้ Python 3.14 ใน `.venv` มี dependency คือ `comtypes`, `Pillow` และ `pystray`

- `recorder.py`
  - ส่วนตรรกะล้วน: `StepBuilder` ทำหน้าที่รวมการพิมพ์ เขียนข้อความขั้นตอนเป็นภาษาไทย และสร้างข้อความของขั้นตอนที่ยังพิมพ์ค้างอยู่ให้รายการแบบสด
  - ส่วนที่เชื่อมกับ Windows: low-level hooks, UI Automation และการถ่ายภาพจอที่เลือก
  - `Recorder` มี `start_recording`, `stop_recording`, `pause`, `live()`, `window_on_selected()`, `hooks_ok` และ `hook_error`
  - ฟังก์ชันเสริม: `find_app_window()` หาหน้าต่าง StepCap จากชื่อหน้าต่าง, `is_own_window()` ใช้ไม่บันทึกหน้าต่างของ StepCap เอง โดยดูจาก PID หรือชื่อหน้าต่าง `StepCap` / `StepCap - ...`
- `app.py`
  - tray ใช้ `pystray`
  - HTTP server ฟังเฉพาะ `127.0.0.1` บนพอร์ตสุ่ม และทุก request ต้องมี token
  - `open_editor()` เปิด Edge ด้วย `--app`
  - `start_rec_ui` / `stop_rec_ui` / `pause_ui` / `select_mon_ui` เป็นจุดเดียวที่ tray, ปุ่มลัด, แผงเล็ก และหน้าเว็บใช้ร่วมกัน
  - API: `/api/status`, `/api/start`, `/api/stop`, `/api/pause`, `/api/monitor`, `/api/guides`, `/api/guide/<id>` (GET และ POST), `/api/guide/<id>/delete`, `/img/<id>/<file>`
  - `stop_rec_ui` เพิ่มค่า `GUIDE_SEQ` ทุกครั้งที่ได้คู่มือใหม่ หน้าเว็บที่เปิดอยู่เห็นค่านี้เปลี่ยนแล้วจะไปที่คู่มือใหม่เอง
- `overlay.py` ใช้ tkinter บนเธรดแยก มีกรอบกระพริบ, toast "Start Record" และแผงเล็กระหว่างบันทึก
  - ทุกหน้าต่างตั้ง `WDA_EXCLUDEFROMCAPTURE` จึงไม่ติดในภาพหน้าจอ (ทดสอบแล้ว: หน้าต่างปกติติดในภาพ 100%, หน้าต่างที่ตั้งค่านี้ติด 0%)
- `editor.html` หน้าเดียวรวมทุกอย่าง:
  - หน้าแรก: แผงควบคุม, รายการแบบสด และรายการคู่มือ
  - หน้าแก้ไข: แก้ข้อความ, ลบหรือลากสลับขั้นตอน, เพิ่มหมายเหตุ, เพิ่ม/ลาก/ลบวง, ตั้งสีและขนาดรายวง, ครอป
  - ดูตัวอย่าง: ใช้ canvas และ `regionFor` ซูมเข้าหาวง
  - Export: HTML ไฟล์เดียว ดาวน์โหลดผ่านเบราว์เซอร์
- เทสต์: `test_steps.py` (ตรรกะล้วน 9 ข้อ) และ `test_windows.py` (เช็กว่าตัวดักติดตั้งได้และรับเหตุการณ์จาก Windows ได้จริง)
- ที่เก็บข้อมูล: `Documents\StepCap\<id>\guide.json` + `<step_id>.png` และโฟลเดอร์ `_tmp` สำหรับไฟล์ชั่วคราวของตัวบันทึก

## 3. เป้าหมาย

### ส่วนที่ 0: หน้าต่างของโปรแกรมเอง
- **หน้าต่างหลัก:** StepCap มีหน้าต่างหลักหน้าต่างเดียว ชื่อ `StepCap` มีไอคอนของตัวเอง ทุกหน้าจอแสดงในหน้าต่างนี้ และ**ต้องไม่มีหน้าต่างเบราว์เซอร์เปิดขึ้นมาอีก**
- **ตอนเปิดโปรแกรม:** แสดงหน้าต่างหลักที่หน้า Home
- **ปุ่ม X:** ซ่อนหน้าต่างไปที่ tray โดยโปรแกรมยังทำงาน และปุ่มลัดยังใช้ได้
  - เมนู tray มี "เปิด StepCap" สำหรับเรียกหน้าต่างกลับมา
  - เมนู tray มี "ออก" สำหรับปิดโปรแกรมจริง ถ้ากำลังบันทึกอยู่ ให้หยุดและบันทึกคู่มือก่อน
- **พฤติกรรมตอนบันทึกเหมือนเดิม:** หน้าต่างหุบลงเป็นแผงเล็กเมื่ออยู่บนจอเดียวกับที่บันทึก ซึ่งจะเป็นแบบนี้ทุกครั้งถ้ามีจอเดียว กดหยุดแล้วหน้าต่างกลับมาเปิดคู่มือใหม่ใน**โหมดแก้ไข**ทันที (ผู้ใช้ตกลงไว้แล้ว เพราะหลังบันทึกเสร็จมักต้องแก้ข้อความ) ส่วนการเปิดคู่มือจากการ์ดหรือรายการ จะเข้าโหมดดูก่อนเสมอตามส่วนที่ 1
- **Export:** เปิดหน้าต่าง "บันทึกเป็น" ของ Windows ให้ผู้ใช้เลือกที่เก็บไฟล์ ข้อนี้แทนข้อตกลงเดิมที่ให้ดาวน์โหลดลงโฟลเดอร์ Downloads
- **ธีมสว่างตลอด:** ไม่เปลี่ยนตามธีมของ Windows หน้าตาอ้างอิงจาก Scribe ธีมสว่าง ได้แก่ พื้นขาว, แถบซ้ายสีเทาอ่อน, เส้นขอบสีเทาอ่อน, การ์ดมุมโค้ง และตัวอักษรเข้ม

### ส่วนที่ 0: หน้าหลักแบบ Scribe
**โครงหน้าจอ**
- **แถบซ้าย:**
  - โลโก้ "StepCap"
  - ช่องค้นหา: ค้นจากชื่อคู่มือและข้อความในขั้นตอน
  - เมนู: **Home**, **คู่มือทั้งหมด**, **ถังขยะ**, **ตั้งค่า**
- **แถบบน:** ไอคอนและชื่อหน้าที่เปิดอยู่ ด้านขวามีปุ่ม **+ บันทึกใหม่**
  - กดแล้วขึ้นตัวเลือกจอ แต่ละจอแสดงขนาด และบอกว่าจอไหนเป็นจอหลัก
  - ชี้หรือกดเลือกจอแล้ว จอนั้นต้องมีกรอบกระพริบเหมือนตอนนี้
  - กด "เริ่มบันทึก" เพื่อเริ่ม ย้ายการเลือกจอจากการ์ดเดิมมาไว้ที่นี่

**หน้า Home**
- **Recents:** คู่มือล่าสุดแสดงเป็นการ์ด แถวละ 4 ใบบนจอกว้าง คู่มือที่บุ๊กมาร์กไว้ขึ้นก่อน ตามด้วยคู่มือที่สร้างใหม่ที่สุด
  - **ในการ์ด:**
    - ไอคอนและชื่อโปรแกรมที่บันทึก
    - ชื่อคู่มือ ยาวได้ไม่เกิน 2 บรรทัด
    - เวลาที่ผ่านมา เช่น "5 นาทีที่แล้ว" หรือ "2 วันที่แล้ว" และจำนวนขั้นตอน
  - **ชี้เมาส์ที่การ์ด:** มุมขวาบนจะมีปุ่ม **บุ๊กมาร์ก** (เปิด/ปิด) และปุ่ม **⋯** ซึ่งมีเมนู เปิด / เปลี่ยนชื่อ / ทำสำเนา / Export / ลบ ไม่มีปุ่มลิงก์เพราะไม่มีการแชร์ออนไลน์
  - **มุมขวาของหัวข้อ:** ปุ่มสลับการ์ดหรือรายการ และต้องจำตัวเลือกล่าสุดไว้
  - **ด้านล่าง:** ปุ่ม "ดูทั้งหมด" ไปหน้าคู่มือทั้งหมด
- **สถิติ:** การ์ดเดียวชื่อ **"คู่มือทั้งหมด"** แสดงจำนวน ไม่นับคู่มือในถังขยะ
- **คำเตือนเมื่อตัวดักทำงานไม่ได้:** แสดงแถบแดงด้านบนเหมือนตอนนี้

**หน้าคู่มือทั้งหมด**
- การ์ดหรือรายการแบบเดียวกับ Recents แต่แสดงคู่มือทุกเล่ม เรียงจากใหม่ไปเก่า
- มีตัวกรอง "เฉพาะที่บุ๊กมาร์ก"
- ใช้ช่องค้นหาในแถบซ้ายกรองได้

**หน้าถังขยะ**
- ลบคู่มือแล้วย้ายไปไว้ที่ `Documents\StepCap\_trash\<id>\` และบันทึกวันที่ลบไว้
- แต่ละรายการมีปุ่ม **กู้คืน** และ **ลบถาวร** ซึ่งส่งไปถังขยะของ Windows เหมือน `recycle()` ตอนนี้
- มีปุ่ม **ล้างถังขยะ** ซึ่งต้องถามยืนยันก่อน
- คู่มือในถังขยะต้องไม่ขึ้นใน Home, ในหน้าคู่มือทั้งหมด และในผลค้นหา

**หน้าตั้งค่า**
- จอเริ่มต้นสำหรับบันทึก ใช้ค่าเดียวกับที่เลือกจาก "+ บันทึกใหม่"
- รายการปุ่มลัด แสดงอย่างเดียว แก้ไม่ได้: `Ctrl+Alt+R` เริ่ม/หยุด, `Ctrl+Alt+P` พัก
- ที่เก็บคู่มือ: แสดง path และมีปุ่ม "เปิดโฟลเดอร์" ใน Explorer ยังเปลี่ยนที่เก็บไม่ได้
- เว้นที่ไว้ให้สวิตช์ "ซ่อนข้อมูลอัตโนมัติ" ซึ่งจะทำในส่วนที่ 3

**ระหว่างบันทึก ในกรณีที่หน้าต่างไม่ได้หุบ** (มีหลายจอ และหน้าต่างอยู่คนละจอกับที่บันทึก)
- ด้านบนของเนื้อหามีแถบ "● กำลังบันทึก" หน้าตาคล้ายแถบแจ้งเตือนของ Scribe
- ในแถบมีรายการขั้นตอนแบบสด พร้อมบรรทัดของข้อความที่ยังพิมพ์ค้าง และปุ่ม พัก/ทำต่อ กับปุ่ม หยุด

**ไอคอนโปรแกรม**
- ตอนบันทึก ให้เก็บ path ของไฟล์ exe ของหน้าต่างที่คลิกด้วย ตอนนี้ `window_info()` ได้ path นี้อยู่แล้วแต่เก็บไว้แค่ชื่อ
- ตอนเขียนคู่มือ ให้ดึงไอคอนจาก exe ของโปรแกรมที่ใช้ตั้งชื่อคู่มือ แล้วบันทึกเป็น `app_icon.png` ในโฟลเดอร์คู่มือ
- ถ้าดึงไม่ได้ ให้ใช้ไอคอนกลางแทน

### ส่วนที่ 1: โหมดดู
เปิดคู่มือจากการ์ดหรือรายการแล้วเข้า**โหมดดู**ก่อนเสมอ ยกเว้นคู่มือที่เพิ่งบันทึกเสร็จ ซึ่งเปิดในโหมดแก้ไขตามส่วนที่ 0 หน้าจอเรียงจากบนลงล่างดังนี้:
- **ชื่อคู่มือ**
- **บรรทัดข้อมูล:** จำนวนขั้นตอน / วันที่สร้าง / วันที่แก้ล่าสุด แสดงเฉพาะรายการที่เปิดสวิตช์ไว้
- **สารบัญ:** แสดงเมื่อเปิดสวิตช์ เป็นรายการเลขขั้นตอนกับข้อความ คลิกแล้วเลื่อนไปที่ขั้นตอนนั้น
- **ขั้นตอน:** เลขขั้นตอน + ข้อความ + **ภาพเต็มจอโดยไม่ซูม** พร้อมวงจุดคลิก
  - ถ้าขั้นตอนนั้นเคยครอปไว้ ให้แสดงภาพที่ครอป
  - ขั้นตอนหมายเหตุแสดงเป็นกล่องเน้นแบบตอนนี้
- **มุมขวาบน:** ปุ่ม **Edit** และ **Export**

ให้ลบปุ่ม/หน้าต่าง "ดูตัวอย่าง" เดิม และการซูมอัตโนมัติด้วย `regionFor` ออก เพราะโหมดดูมาแทนแล้ว แต่ยังต้องใช้ crop ได้

### ส่วนที่ 1: โหมดแก้ไข
- **กด Edit:** เข้าหน้าแก้ไข ซึ่งต้องใช้ความสามารถเดิมได้ครบทุกอย่าง ปุ่ม Edit เปลี่ยนเป็น **Done**
- **แถบเครื่องมือลอย:** เรียงแนวตั้งทางขวาเหมือน Scribe มี tooltip ภาษาไทยทุกปุ่ม มี 3 ปุ่ม:
  1. **Add to Page** — แสดงไว้แต่กดไม่ได้ tooltip เขียนว่า "เร็วๆ นี้" จะใช้ได้ในส่วนที่ 5
  2. **สีวงจุดคลิก**
     - กดแล้วขึ้นชุดสีสำเร็จรูป โดยมี `#FB923C` เป็นสีเริ่มต้น และมีช่องเลือกสีหรือใส่รหัสสีเอง
     - เลือกแล้ว**เปลี่ยนสีทุกวงในคู่มือทันที** และวงที่เพิ่มใหม่หลังจากนั้นใช้สีนี้ด้วย
     - หลังจากนั้นยังแก้สีรายวงได้เหมือนเดิม
  3. **ตั้งค่าเอกสาร**
     - สวิตช์ 4 อัน: สารบัญ / จำนวนขั้นตอน / วันที่สร้าง / วันที่แก้ล่าสุด
     - ตัวเลือกมุมมอง **Linear** หรือ **Grid**
- **มุมมอง Grid:**
  - ใช้ในโหมดแก้ไขเท่านั้น
  - แสดงขั้นตอนเป็นภาพย่อ แถวละ 3 ใบ แต่ละใบมีเลขขั้นตอนกับข้อความสั้น ขั้นตอนที่ไม่มีภาพให้แสดงเป็นการ์ดข้อความ
  - ลากเพื่อสลับลำดับได้
  - คลิกที่ใบไหน ให้สลับเป็นมุมมอง Linear แล้วเลื่อนไปที่ขั้นตอนนั้น
  - จำมุมมองที่เลือกไว้แยกตามคู่มือ
- **กด Done:** กลับโหมดดู บันทึกอัตโนมัติเหมือนเดิม
- **Export:** หน้าตาเหมือนโหมดดูทุกอย่าง คือภาพเต็มจอ, ภาพที่ครอป, และสารบัญหรือข้อมูลตามสวิตช์ ได้เป็นไฟล์ HTML เดียวที่ฝังภาพไว้แล้ว และบันทึกผ่านหน้าต่าง "บันทึกเป็น"

### ข้อมูลที่เพิ่มใน guide.json
```json
{ "updated": "2026-10-15T16:02:11",
  "bookmarked": false,
  "app": "Notepad", "app_icon": "app_icon.png" | null,
  "settings": { "toc": false, "step_count": false, "created": false, "updated": false,
                "layout": "linear", "click_color": "#FB923C" } }
```
- `updated`: ฝั่ง server ตั้งค่าใหม่ทุกครั้งที่บันทึก
- **คู่มือเก่าที่ไม่มีฟิลด์เหล่านี้:** ต้องเปิดใช้งานได้ โดยใช้ค่าเริ่มต้นแทนฟิลด์ที่ไม่มี ตอนนี้ผู้ใช้มีคู่มือจริงอยู่แล้ว **ห้ามทำให้คู่มือเหล่านั้นเสียหาย**

## 4. สิ่งที่ไม่ทำในรอบนี้ และสิ่งที่ห้ามเกิดขึ้น

**ไม่ทำในรอบนี้**
- ส่วนที่ 2–5
- ชื่อผู้เขียน (ข้อ 14), เวลาของแต่ละขั้นตอน (ข้อ 17), branding (ข้อ 19) — ผู้ใช้ตัดออกแล้ว
- การแชร์ออนไลน์, ทีม, สถิติยอดดู, Insights, Tasks, AI ทุกชนิด
- การเปลี่ยนปุ่มลัด และการย้ายที่เก็บคู่มือ

**ห้ามเกิดขึ้น ถ้าเกิดถือว่างานล้มเหลวแม้โค้ดจะทำงานได้**
- มีหน้าต่างเบราว์เซอร์แยกเปิดขึ้นมา
- หน้าต่าง StepCap, แผงเล็ก หรือ overlay ใดๆ ติดลงไปในภาพของคู่มือ
- การคลิกหรือการพิมพ์ในหน้าต่าง StepCap ถูกบันทึกเป็นขั้นตอน ข้อนี้ต้องยังใช้ได้หลังเปลี่ยนเป็นหน้าต่างใหม่ เพราะหน้าต่างอยู่ใน process ของเราแล้ว จึงเข้าเงื่อนไขการเช็ก PID
- คู่มือเดิมของผู้ใช้เปิดไม่ได้หรือข้อมูลหาย
- ปุ่มลัด, tray หรือแผงเล็กใช้ไม่ได้
- กด X แล้วโปรแกรมปิดทั้งที่กำลังบันทึกอยู่

## 5. ข้อจำกัด
- Windows 11 และ Python 3.14 ใน `.venv` ที่มีอยู่
- ตอนนี้ต่อจอเดียว แต่ต้องรองรับหลายจอ ผู้ใช้เคยใช้ 3 จอ
- ข้อความทั้งหมดบนหน้าจอเป็นภาษาไทย
- ทำงานในเครื่องเท่านั้น ไม่ต้องใช้อินเทอร์เน็ตตอนใช้งาน
- อนุญาตให้เพิ่ม dependency **`pywebview`** (พร้อม `pythonnet` และตัวอื่นที่มันต้องใช้)
  - ตรวจแล้ว: `pip --dry-run` ได้ pywebview 6.2.1 และ pythonnet 3.2.1 เป็น wheel ใช้กับ Python 3.14 ได้
  - ตรวจแล้ว: เครื่องมี WebView2 Runtime 155 อยู่ที่ `C:\Program Files (x86)\Microsoft\EdgeWebView\Application\`
  - ห้ามเพิ่ม UI framework อื่น เช่น PySide6 หรือ Electron
- `test_steps.py` และ `test_windows.py` ต้องยังผ่าน ตรรกะใหม่ที่ไม่ง่าย เช่น ถังขยะ/กู้คืน, การเติมค่าเริ่มต้นให้คู่มือเก่า และเวลาที่ผ่านมา ต้องมีเทสต์อย่างน้อยหนึ่งชุดที่รันได้

## 6. สิ่งที่ผู้ออกแบบตัดสินใจเอง (ผู้ใช้ไม่ได้เป็นคนเลือก)
- **ที่เก็บค่าตั้ง:** เก็บไว้ฝั่ง server ในไฟล์ `Documents\StepCap\settings.json` ไม่ใช้ `localStorage` เพราะ pywebview ล้างค่าในนั้นทุกครั้งที่ปิดโปรแกรม ค่าที่เก็บมี:
  - จอเริ่มต้น เก็บด้วยชื่ออุปกรณ์ เช่น `\\.\DISPLAY1` ไม่เก็บเป็นเลขลำดับ ถ้าหาจอนั้นไม่เจอให้ใช้จอหลัก
  - ตัวเลือกการ์ดหรือรายการ
- **ซ่อนหน้าต่างหลักจากภาพหน้าจอ:** ตั้งค่านี้เฉพาะระหว่างบันทึก ส่วนเวลาอื่นให้ยังแชร์หน้าจอโปรแกรมนี้ได้ตามปกติ
- **เปิดโปรแกรมได้ครั้งละหนึ่งตัว:** ถ้าเปิดซ้ำ ให้เรียกหน้าต่างที่เปิดอยู่ขึ้นมาแทน เพราะการกด X แค่ซ่อนหน้าต่างไปที่ tray
- **หมายเหตุ:** ไม่มีเลขขั้นตอน ไม่นับในจำนวนขั้นตอน และไม่อยู่ในสารบัญ ตอนนี้โค้ดทำเรื่องนี้ไม่ตรงกัน 3 แบบ ให้ใช้หลักนี้ทุกที่ ทั้งโหมดดู โหมดแก้ไข และ Export
- **ไอคอนและชื่อโปรแกรมบนการ์ด:**
  - คู่มือเก่าที่ไม่มีข้อมูลนี้ ให้ใช้ไอคอนกลาง และใช้ชื่อโปรแกรมจากคำที่อยู่ก่อน " - " ในชื่อคู่มือ
  - ถ้าโปรแกรมเป็นตัวกลางที่รันแอปอื่นอยู่ข้างใน เช่น `ApplicationFrameHost` หรือ `StartMenuExperienceHost` ให้ใช้ไอคอนกลาง ส่วนข้อความในขั้นตอนไม่ต้องแก้ในรอบนี้
- **ข้ามโฟลเดอร์ระบบตอนแสดงรายการคู่มือ:** ข้ามโฟลเดอร์ที่ขึ้นต้นด้วย `_` ได้แก่ `_tmp`, `_trash` และ `_browser` ที่ Edge เคยใช้ ส่วน `_browser` ไม่ต้องลบ

## 7. สิ่งที่ให้ผู้สร้างตัดสินใจเอง
- จะใช้ HTTP server กับ token เดิมต่อ หรือย้ายไปใช้ `js_api` ของ pywebview
- การจัดเธรด: pywebview ต้องใช้ main thread บน Windows ส่วน `pystray` กับ tkinter overlay ย้ายไปเธรดอื่นได้
- ใช้วิธีไหนหุบหรือคืนหน้าต่าง เช่น `window.minimize()` / `restore()` ของ pywebview หรือ Win32 ก็ได้ ขอแค่พฤติกรรมเป็นตามข้อ 3
- จำนวนการ์ดใน Recents ประมาณ 8 ใบ, ชุดสีสำเร็จรูป, ไอคอนต่างๆ (ใช้ SVG ในไฟล์), ขนาดและระยะห่างต่างๆ ให้ดูตามภาพ Scribe ธีมสว่าง
- รูปแบบเวลาที่ผ่านมาที่ละเอียดกว่าตัวอย่างในข้อ 3, ชื่อของสำเนา เช่น "<ชื่อ> (สำเนา)", และวิธีสร้าง id ของสำเนา
- จะแยก `editor.html` เป็นหลายไฟล์ไหม ถ้าแยกแล้วอ่านง่ายขึ้นจริง
