# StepCap — ส่วนที่ 4: ส่งออกเป็น PDF, Markdown และ Word

สถานะ: ผู้ใช้อนุมัติแล้ว (2026-10-16) · สร้างแล้ว รอผู้ใช้ทดสอบจริง · ต่อจากส่วนที่ 3 (`2026-10-16-auto-redaction-design.md` ผู้ใช้ทดสอบผ่านและ merge แล้ว PR #1)

## 1. ที่มาและเหตุผล

ตอนนี้ส่งออกคู่มือได้แบบเดียวคือไฟล์ HTML ไฟล์เดียว ส่วนนี้เพิ่มอีก 3 แบบตามแผนเดิม: **PDF, Markdown และ Word** เพื่อส่งให้คนที่เปิดไฟล์ด้วยโปรแกรมอื่น เช่น อ่านบนมือถือ แนบอีเมล หรือแก้ต่อใน Word

ผู้ใช้ข้ามรอบคำถามและให้เริ่มเลย ทุกการตัดสินใจในเอกสารนี้นอกจาก "ต้องมี 3 แบบนี้" จึงเป็นของผู้ออกแบบ ดูข้อ 6

## 2. สิ่งที่มีอยู่แล้ว (ที่เกี่ยวกับส่วนนี้)

- **`ui/guide.js`:**
  - `renderStepPng(step, gid)` วาดภาพสุดท้ายของขั้นตอนเป็น PNG (ครอป วง ลูกศร กรอบ ข้อความ เบลอ ปิดดำ ลงในพิกเซลแล้ว)
  - `buildExportHtml(gid)` สร้าง HTML ไฟล์เดียวที่หน้าตาเหมือนโหมดดู ทุกภาพที่ไม่ใช่ GIF ผ่าน `renderStepPng` ก่อน จึงไม่มีพิกเซลต้นฉบับหลุด
  - `exportGuide(gid)` ส่ง HTML ไปที่ `POST /api/guide/<id>/export` แล้วเปิดหน้าต่าง "บันทึกเป็น"
  - ปุ่ม "ส่งออก" อยู่ที่หน้าคู่มือ (ทั้งโหมดดูและโหมดแก้ไข) และในเมนูของการ์ดคู่มือที่หน้าหลัก
- **`renderGuide`:** ชื่อคู่มือ, บรรทัดข้อมูล (จำนวนขั้นตอน วันที่สร้าง วันที่แก้ไข ตามตั้งค่าเอกสาร), สารบัญ (ถ้าเปิด), ขั้นตอนมีเลข, หมายเหตุไม่มีเลข, GIF แสดงตามจริง
- **`app.save_as(filename, data, file_type)`:** หน้าต่าง "บันทึกเป็น" ของ Windows ถ้าเขียนไฟล์ไม่สำเร็จตอนนี้ไม่แจ้ง (ข้อบกพร่องเล็กที่เลื่อนไว้จากส่วนที่ 2)
- **ประตูกันของส่วนที่ 3:** คู่มือที่กำลังซ่อนข้อมูลเปิดหรือส่งออกไม่ได้ (ตอบ 409)

## 3. เป้าหมาย

### 3.1 เลือกรูปแบบ
- กด "ส่งออก" แล้วมีเมนูให้เลือก: **HTML, PDF, Markdown, Word** ทั้งที่หน้าคู่มือและที่การ์ดหน้าหลัก
- ไฟล์ตั้งชื่อตามชื่อคู่มือ เลือกที่เก็บด้วยหน้าต่าง "บันทึกเป็น" เหมือนเดิม
- ระหว่างทำมีข้อความ "กำลังส่งออก…" และกดส่งออกซ้ำไม่ได้จนกว่าจะเสร็จ เสร็จแล้วแจ้ง "บันทึกไฟล์แล้ว" ถ้าไม่สำเร็จแจ้งว่า "ส่งออกไม่สำเร็จ" พร้อมเหตุผลสั้นๆ (ใช้กับ HTML และการดาวน์โหลดภาพด้วย)

### 3.2 เนื้อหาทุกรูปแบบเหมือนโหมดดู
- ชื่อคู่มือ, บรรทัดข้อมูล และสารบัญ ตามตั้งค่าเอกสารของคู่มือนั้น
- ขั้นตอนมีเลขและข้อความ ตามด้วยภาพ หมายเหตุไม่มีเลขและดูต่างจากขั้นตอน
- **ภาพทุกภาพเป็นภาพสุดท้ายที่ซ่อนข้อมูลแล้ว** (ผ่าน `renderStepPng`) ไม่มีพิกเซลต้นฉบับหลุดไปในไฟล์ใดเลย กฎเดิมของส่วนที่ 2
- ภาพที่อ่านไม่ได้: ส่งออกขั้นตอนนั้นโดยไม่มีภาพ และแจ้งตอนเสร็จว่า "ภาพของขั้นที่ 3 อ่านไม่ได้"

### 3.3 PDF
- กระดาษ A4 แนวตั้ง ภาพย่อให้พอดีความกว้างหน้า ขั้นตอนหนึ่งไม่ถูกตัดกลางระหว่างสองหน้าถ้าพอดีหน้าเดียว
- ภาษาไทยแสดงถูกต้อง สระและวรรณยุกต์ไม่ลอย (ทดลองแล้ว ดูข้อ 6)
- GIF ใช้ภาพแรก (PDF เคลื่อนไหวไม่ได้)
- สารบัญคลิกไปยังขั้นตอนได้

### 3.4 Markdown
- ได้ไฟล์ **.zip** หนึ่งไฟล์ ข้างในมี `<ชื่อคู่มือ>.md` และโฟลเดอร์ `images/` ที่มี `step-01.png`, `step-02.png`, …
- ในไฟล์ .md: `# ชื่อ`, บรรทัดข้อมูล, สารบัญเป็นรายการลิงก์, ขั้นตอนเป็น `## 1. ข้อความ` ตามด้วยภาพแบบลิงก์สัมพัทธ์, หมายเหตุเป็น `> ข้อความ`
- อักขระพิเศษของ Markdown ในข้อความขั้นตอนต้องไม่ทำให้รูปแบบเพี้ยน
- GIF คงเป็น GIF เคลื่อนไหวเหมือนต้นฉบับ (`step-05.gif`)

### 3.5 Word (.docx)
- ชื่อคู่มือเป็นหัวเรื่อง, บรรทัดข้อมูล, สารบัญเป็นรายการตัวเลขของข้อความขั้นตอน
- ขั้นตอน: เลขและข้อความตัวหนา ตามด้วยภาพกว้างไม่เกินขอบหน้า
- หมายเหตุ: ย่อหน้าตัวเอียงมีพื้นสีอ่อน
- ฟอนต์ภาษาไทยตั้งไว้ให้ Word แสดงไทยถูก (Leelawadee UI) และแก้ข้อความต่อใน Word ได้ตามปกติ
- GIF ใช้ภาพแรก

## 4. สิ่งที่ไม่ทำในรอบนี้ และสิ่งที่ห้ามเกิดขึ้น

**ไม่ทำ**
- ส่งออกหลายคู่มือรวมเป็นไฟล์เดียว (เป็นเรื่องของส่วนที่ 5 Pages)
- เลือกขนาดกระดาษ แนวนอน หรือหัว/ท้ายกระดาษใน PDF
- สารบัญแบบฟิลด์ของ Word ที่ต้องกดอัปเดต
- Markdown แบบไฟล์เดียวที่ฝังภาพในข้อความ (base64) หรือโฟลเดอร์แทน .zip
- ส่งออกไปที่บริการออนไลน์ใดๆ

**ห้ามเกิดขึ้น**
- พิกเซลต้นฉบับของส่วนที่ซ่อนไว้หลุดไปในไฟล์ใดเลย รวมถึงภาพใน .zip และ .docx
- เปิดเบราว์เซอร์ หรือมีหน้าต่างโผล่ขึ้นมาระหว่างทำ PDF (ใช้หน้าต่างที่ซ่อนไว้ของโปรแกรมเอง)
- ส่งออกไม่สำเร็จแล้วไม่แจ้ง
- ไฟล์ส่งออกเก็บ path ในเครื่อง ชื่อผู้ใช้ Windows หรือข้อมูลอื่นนอกจากเนื้อหาคู่มือ
- เทสต์ไปคลิกหรือพิมพ์บนเดสก์ท็อปจริง หรือแตะคู่มือจริงใน `Documents\StepCap`

## 5. ข้อจำกัด

- Windows 11, Python 3.14 ใน `.venv`, ทำงานในเครื่องเท่านั้น
- PDF: `CoreWebView2.PrintToPdfAsync` ของ WebView2 ผ่านหน้าต่าง pywebview ที่ซ่อนไว้ (pywebview 6.2.1) ทดลองแล้วได้ PDF ภาษาไทยถูกต้องและขึ้นหน้าใหม่ได้
- Word: `python-docx` 1.2.0 (ต้องใช้ `lxml` ซึ่งมี wheel สำหรับ cp314 แล้ว) เพิ่มลง `requirements.txt`
- Markdown/.zip: ใช้ `zipfile` ของ Python
- ข้อความใน UI เป็นภาษาไทยทั้งหมด ชนิดไฟล์ในหน้าต่าง "บันทึกเป็น" ต้องเป็นตัวอักษรอังกฤษ (pywebview อ่านสระไทยในตัวกรองไม่ได้)
- เทสต์ใช้ `STEPCAP_STORAGE` ชี้โฟลเดอร์ชั่วคราว และใช้ภาพที่สร้างในเทสต์เท่านั้น

## 6. สิ่งที่ผู้ออกแบบตัดสินใจเอง (ผู้ใช้ไม่ได้เป็นคนเลือก)

- **PDF ทำด้วย WebView2 ของโปรแกรมเอง** ไม่ใช่ไลบรารี PDF ใน Python เพราะไลบรารีอย่าง reportlab วางสระ/วรรณยุกต์ไทยผิดบ่อย ส่วน WebView2 ใช้ตัววาดตัวอักษรเดียวกับหน้าต่างโปรแกรม ทดลองแล้วไทยถูกต้อง และไม่ต้องเปิดเบราว์เซอร์
- **PDF ใช้ HTML ที่ส่งออกอยู่แล้วเป็นต้นทาง** เพิ่มแค่ CSS สำหรับพิมพ์ หน้าตาจึงเหมือนไฟล์ HTML และโหมดดู
- **Markdown เป็น .zip** เพราะ .md อ้างภาพได้แค่เป็นไฟล์ข้างๆ ไฟล์เดียวส่งต่อง่ายกว่าโฟลเดอร์
- **Word ใช้ python-docx** แทนการเขียนไฟล์ docx เอง เพราะโครงสร้างไฟล์ซับซ้อน เขียนเองพลาดง่าย
- **ภาพทำในหน้าเว็บ ประกอบไฟล์ใน Python:** หน้าเว็บสร้าง PNG สุดท้ายของทุกขั้นด้วย `renderStepPng` เดิม (ตัวที่ผ่านเทสต์การซ่อนข้อมูลแล้ว) แล้วส่งให้ Python ประกอบ .zip/.docx จะได้มีที่เดียวที่วาดภาพสุดท้าย
- **GIF ใน PDF และ Word ใช้ภาพแรก** ใน Markdown คง GIF เดิมไว้
- **แก้ "บันทึกเป็น ล้มเหลวแล้วไม่แจ้ง" ไปด้วย** เพราะทุกรูปแบบใช้ `save_as` ตัวเดียวกัน
- **ปุ่มส่งออกเป็นเมนูเลือกรูปแบบทุกครั้ง** ไม่จำรูปแบบที่ใช้ล่าสุด

## 7. สิ่งที่ให้ผู้สร้างตัดสินใจเอง

- วิธีส่ง PNG หลายภาพจากหน้าเว็บไป Python (JSON base64 หรือแบบอื่น) ให้รับคู่มือ 100 ขั้นที่ภาพขนาด 4K ได้
- วิธีเปิดและรอหน้าต่างซ่อนสำหรับพิมพ์ PDF และการลบไฟล์ชั่วคราวหลังเสร็จ
- CSS สำหรับพิมพ์ (ระยะขอบ ขนาดภาพ การกันขั้นตอนขาดกลางหน้า)
- การ escape อักขระ Markdown ในข้อความ
- ขนาดภาพใน Word (ไม่เกินความกว้างหน้าระหว่างขอบ)
- หน้าตาของเมนูเลือกรูปแบบ ให้เข้ากับเมนูที่มีอยู่
- เทสต์: ตรวจเนื้อหาไฟล์ที่ได้ (ข้อความใน .md, ภาพใน .zip และ .docx, หน้าใน PDF) และตรวจว่าภาพในทุกรูปแบบไม่มีพิกเซลเดิมของส่วนที่ซ่อน (เหมือน `test_export_contains_no_original`)
