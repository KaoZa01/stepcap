# StepCap — ส่วนที่ 3: ซ่อนข้อมูลอัตโนมัติ

สถานะ: ผู้ใช้อนุมัติแล้ว (2026-10-16) · สร้างแล้ว รอผู้ใช้ทดสอบจริง · ต่อจากส่วนที่ 2 (`2026-10-15-image-editor-design.md` ผู้ใช้ทดสอบผ่านและ merge เข้า main แล้ว)

## 1. ที่มาและเหตุผล

ก่อนส่งคู่มือให้คนอื่น ผู้ใช้ต้องไล่เบลอข้อมูลส่วนตัวในภาพเองทีละขั้น ส่วนที่ 2 ทำให้เบลอ/ปิดดำด้วยมือได้แล้ว ส่วนนี้ให้โปรแกรมหาข้อมูลที่ควรซ่อนแล้วเบลอให้เอง โดยใช้**กฎรูปแบบตัวอักษร** (เช่น รูปแบบอีเมล เลขบัตร) ไม่ใช้ AI

ผู้ใช้ข้ามรอบคำถามและให้เริ่มเลย จึงตัดสินใจเองเพียงข้อเดียวคือ **วิธีหาตัวอักษรในภาพ: ใช้ OCR ของ Windows** (อ่านตัวอักษรจากภาพที่บันทึกไว้ ทำงานในเครื่อง) ส่วนการตัดสินใจอื่นทั้งหมดในเอกสารนี้เป็นของผู้ออกแบบ ดูข้อ 6

## 2. สิ่งที่มีอยู่แล้ว (ที่เกี่ยวกับส่วนนี้)

- **`step.redactions`:** `[{"type":"blur"|"black","x","y","w","h"}]` เป็นพิกัดในภาพเต็ม (ก่อนครอป) ส่วนที่ 2 ออกแบบลิสต์นี้ไว้ให้ส่วนที่ 3 เพิ่มรายการเข้าไปได้
- **การวาดและส่งออก:** `drawStepCanvas` วาดเบลอ/ปิดดำ และไฟล์ส่งออกกับไฟล์ดาวน์โหลดใช้ภาพที่ผ่านการซ่อนแล้วเท่านั้น ไม่มีพิกเซลเดิมหลุด (`test_render.py` ตรวจไว้แล้ว รวมถึงเบลอชิดขอบภาพ)
- **หน้าแก้ไขภาพ (`ui/editor.js`):** เลือก ย้าย ปรับขนาด ลบ และย้อนกลับรายการเบลอได้แล้ว
- **การบันทึก (`recorder.py`):** เก็บภาพไว้ใน `_tmp` ระหว่างบันทึก แล้ว `stop_recording()` → `_write_guide()` ย้ายภาพเข้าโฟลเดอร์คู่มือ จากนั้น `app.stop_rec_ui()` เปิดคู่มือในโหมดแก้ไข
- **ข้อความของขั้นตอนพิมพ์:** `_Typing.text()` เก็บสิ่งที่พิมพ์ไว้ตรงๆ เช่น `พิมพ์ "me@mail.com" ในช่อง "อีเมล"` ช่องรหัสผ่านไม่เก็บตัวอักษรอยู่แล้ว
- **หน้าตั้งค่า (`ui/shell.js`):** มีที่เว้นไว้ "ซ่อนข้อมูลอัตโนมัติ" เป็นสวิตช์ที่ยังกดไม่ได้ ("เร็วๆ นี้")
- **การตั้งค่าโปรแกรม:** `settings.json` ผ่าน `library.load_settings/save_settings` รับเฉพาะคีย์ใน `DEFAULT_APP_SETTINGS`

## 3. เป้าหมาย

### 3.1 สิ่งที่หา (กฎ)
แต่ละกฎเปิด/ปิดแยกกันได้ในหน้าตั้งค่า
- **อีเมล**
- **เบอร์โทรศัพท์ไทย:** มือถือและเบอร์บ้าน ทั้งแบบมีขีด เว้นวรรค และขึ้นต้น +66
- **เลขบัตรประชาชน 13 หลัก:** ต้องผ่านการตรวจหลักสุดท้าย (checksum) จึงจะนับ เพื่อไม่ให้เบลอตัวเลขยาวทั่วไป
- **เลขบัตรเครดิต/เดบิต 13–19 หลัก:** ต้องผ่าน Luhn
- **เลขบัญชีธนาคาร 10 หลัก:** แบบ `xxx-x-xxxxx-x` หรือ 10 หลักติดกัน
- **คำที่กำหนดเอง:** ผู้ใช้พิมพ์คำไว้ บรรทัดละคำ เช่น ชื่อบริษัท ชื่อเครื่อง ชื่อผู้ใช้ ไม่สนตัวพิมพ์เล็ก/ใหญ่ คำภาษาไทยจับได้เฉพาะในข้อความของขั้นตอนพิมพ์ ไม่จับในภาพ

### 3.2 ซ่อนในภาพ
- ทุกส่วนที่ตรงกฎถูกเพิ่มเป็นรายการ**เบลอ**ใน `step.redactions` โดยขยายขอบออกเล็กน้อยให้คลุมตัวอักษรทั้งหมด
- รายการที่เพิ่มอัตโนมัติเป็นรายการเบลอธรรมดา ย้าย ปรับขนาด ลบ หรือย้อนกลับได้เหมือนเบลอที่ทำด้วยมือ ผู้ใช้ลบรายการที่เบลอเกินได้เอง
- ภาพต้นฉบับยังอยู่ในเครื่องตามเดิม ไฟล์ส่งออกและไฟล์ดาวน์โหลดต้องไม่มีพิกเซลเดิมของส่วนที่เบลอ (กฎเดิมของส่วนที่ 2)

### 3.3 ทำงานเมื่อไหร่
เมื่อเปิดสวิตช์ "ซ่อนข้อมูลอัตโนมัติ":
- **หลังกดหยุดบันทึก:** ทุกภาพของคู่มือใหม่ผ่านการหาก่อนผู้ใช้จะเห็นคู่มือ หน้าต่างโปรแกรมแสดง "กำลังซ่อนข้อมูล… 3/20" ระหว่างทำ แล้วจึงเปิดคู่มือในโหมดแก้ไขเหมือนเดิม
- **ภาพที่เพิ่มหรือเปลี่ยนทีหลัง:** ทั้งการวางภาพด้วย Ctrl+V การเพิ่มขั้นตอนภาพ และการเปลี่ยนภาพในหน้าแก้ไขภาพ
- **ข้อความของขั้นตอนพิมพ์:** สิ่งที่พิมพ์ซึ่งตรงกฎ แสดงเป็น `•••` แทน เช่น `พิมพ์ "•••" ในช่อง "อีเมล"` และไม่เก็บตัวอักษรจริงไว้ในไฟล์คู่มือ (ทำตอนบันทึกเท่านั้น)

ไม่ว่าสวิตช์จะเปิดหรือปิด:
- **ปุ่ม "ซ่อนข้อมูลอัตโนมัติ" ในหน้าแก้ไขภาพ:** ใช้กับภาพของขั้นตอนนี้ (สำหรับคู่มือเก่า) ย้อนกลับได้ด้วย Ctrl+Z กดซ้ำไม่เพิ่มเบลอซ้อนตรงที่เบลอไว้แล้ว และแจ้งผลว่า "ซ่อนเพิ่ม 3 จุด" หรือ "ไม่พบข้อมูลที่ต้องซ่อน"

### 3.4 หน้าตั้งค่า
แทนที่ "เร็วๆ นี้" ด้วย:
- สวิตช์ **ซ่อนข้อมูลอัตโนมัติ**
- ช่องติ๊กของแต่ละกฎในข้อ 3.1
- ช่อง **คำที่กำหนดเอง**
- ข้อความสั้น: "อ่านได้เฉพาะตัวอักษรอังกฤษและตัวเลข ตรวจภาพอีกครั้งก่อนส่งให้คนอื่น"

### 3.5 ห้ามเงียบ (ข้อห้ามพลาด)
ถ้าซ่อนข้อมูลไม่ได้ ผู้ใช้ต้องรู้ ห้ามปล่อยให้เข้าใจว่าภาพปลอดภัยแล้ว:
- เครื่องไม่มี OCR ภาษาอังกฤษ หรือโหลดไลบรารีไม่ได้: สวิตช์ในหน้าตั้งค่าบอกว่า "ใช้ไม่ได้บนเครื่องนี้" พร้อมเหตุผลสั้นๆ และหลังบันทึกเสร็จมีข้อความแจ้งในคู่มือ
- ภาพไหนอ่านไม่สำเร็จ: คู่มือยังเปิดได้ แต่แจ้งว่า "ซ่อนข้อมูลไม่สำเร็จ X ภาพ" และบอกว่าเป็นขั้นตอนไหน
- GIF: ข้ามไป (แก้ GIF ไม่ได้อยู่แล้ว) และนับรวมในข้อความแจ้ง

## 4. สิ่งที่ไม่ทำในรอบนี้ และสิ่งที่ห้ามเกิดขึ้น

**ไม่ทำ**
- อ่านตัวอักษรภาษาไทยในภาพ (OCR ของ Windows ไม่รองรับภาษาไทย ตรวจบนเครื่องนี้แล้ว: มีแค่ `en-US`)
- หาชื่อคน ที่อยู่ ใบหน้า หรืออะไรที่ต้องใช้ AI เดา
- ปุ่มซ่อนทั้งคู่มือในครั้งเดียวสำหรับคู่มือเก่า (ใช้ปุ่มในหน้าแก้ไขภาพทีละขั้นไปก่อน)
- เลือกได้ว่าจะซ่อนแบบปิดดำแทนเบลอ (เปลี่ยนเองทีละรายการก็ยังไม่ได้ ต้องลบแล้ววาดปิดดำเอง)
- ซ่อนข้อความในขั้นตอนที่ผู้ใช้แก้เองทีหลัง

**ห้ามเกิดขึ้น**
- ส่งภาพหรือข้อความออกนอกเครื่อง
- ซ่อนไม่สำเร็จแล้วไม่แจ้ง (ข้อ 3.5)
- ผู้ใช้เปิดคู่มือใหม่แล้วส่งออกได้ก่อนการหาจะเสร็จ
- เก็บตัวอักษรที่ตรงกฎของขั้นตอนพิมพ์ไว้ในไฟล์คู่มือ เมื่อสวิตช์เปิด
- เทสต์ไปคลิกหรือพิมพ์บนเดสก์ท็อปจริง หรือแตะคู่มือจริงใน `Documents\StepCap`

## 5. ข้อจำกัด

- Windows 11, Python 3.14 ใน `.venv`, ทำงานในเครื่องเท่านั้น, ไม่มี AI แบบแชตหรือบริการออนไลน์
- OCR: `Windows.Media.Ocr` ผ่านแพ็กเกจ `winrt-Windows.Media.Ocr` และแพ็กเกจ `winrt-*` ที่ต้องใช้คู่กัน (มี wheel สำหรับ cp314 รุ่น 3.2.1 ตรวจแล้ว) เพิ่มลง `requirements.txt`
- ข้อความใน UI เป็นภาษาไทยทั้งหมด ธีมสว่าง ทุกอย่างอยู่ในหน้าต่างโปรแกรม
- เทสต์ใช้ `STEPCAP_STORAGE` ชี้โฟลเดอร์ชั่วคราว และใช้ภาพที่สร้างขึ้นในเทสต์เท่านั้น ห้ามใส่ภาพหน้าจอจริงลง repo (repo เป็น public)

## 6. สิ่งที่ผู้ออกแบบตัดสินใจเอง (ผู้ใช้ไม่ได้เป็นคนเลือก)

- **ค่าเริ่มต้น:** สวิตช์เปิด และทุกกฎเปิด ยกเว้นคำที่กำหนดเองซึ่งว่างไว้ เพราะเบลอเกินแก้ง่ายกว่าข้อมูลหลุด
- **ชุดกฎในข้อ 3.1:** เลือกจากสิ่งที่พบบ่อยในหน้าจอคนไทย และเลือกกฎที่มีตัวตรวจเลข (checksum/Luhn) เพื่อลดการเบลอผิด
- **ซ่อนแบบเบลอ** เหมือน Scribe ไม่ใช่ปิดดำ
- **การตั้งค่าเป็นของทั้งโปรแกรม** (`settings.json`) ไม่ใช่ของแต่ละคู่มือ เพราะหน้าตั้งค่าเว้นที่ไว้ตรงนั้นแล้ว
- **หาหลังกดหยุดบันทึก** ไม่ใช่ระหว่างบันทึก เพราะถ้าทำระหว่างบันทึก งานอ่านภาพจะไปถ่วงการอ่านชื่อปุ่มที่คลิก แล้วชื่อขั้นตอนจะผิด
- **ปิดบังข้อความของขั้นตอนพิมพ์ด้วย** ทั้งที่ผู้ใช้ไม่ได้ขอ เพราะอีเมลที่พิมพ์จะหลุดผ่านข้อความแม้ภาพจะเบลอแล้ว ตัดออกได้ถ้าไม่ต้องการ
- **ไม่ทำวิธีอ่านจากหน้าต่างตอนบันทึก (UIA):** ทดลองแล้วอ่านหน้าต่าง VS Code ใช้ ~280 ms ต่อครั้ง ถ้าหน้าจอเปลี่ยนเร็วกว่านั้นกรอบจะเลื่อนจนข้อมูลหลุด

## 7. สิ่งที่ให้ผู้สร้างตัดสินใจเอง

- รูปแบบ regex ของแต่ละกฎ และวิธีจับคู่ข้อความที่ OCR แยกเป็นหลายคำ (เช่น เบอร์ที่มีเว้นวรรค) กลับไปเป็นกรอบในภาพ
- ขยายขอบกรอบกี่พิกเซล ต้องคลุมตัวอักษรครบโดยไม่กินพื้นที่รอบข้างมากเกิน
- ภาพใหญ่หรือตัวอักษรเล็กต้องขยายภาพก่อนส่ง OCR หรือไม่ (`OcrEngine.MaxImageDimension`)
- วิธีส่งงานระหว่าง Python กับหน้าเว็บ ข้อสำคัญคือห้ามมีสองฝั่งเขียน `guide.json` ชนกัน: หลังบันทึกให้ Python เขียนผลก่อนเปิดคู่มือ ส่วนภาพที่เพิ่มทีหลังให้หน้าเว็บขอผลจากเซิร์ฟเวอร์แล้วใส่เองใน `STATE`
- จะบอกว่ารายการเบลอนี้เพิ่มอัตโนมัติไว้ในข้อมูลหรือไม่ (เช่น `"auto": true`) ถ้าใส่ ต้องไม่ทำให้ไฟล์คู่มือเก่าหรือการส่งออกเสีย
- หน้าตาของหน้าจอ "กำลังซ่อนข้อมูล…" และข้อความแจ้งผล ให้เข้ากับธีมเดิม
- เทสต์: ฟังก์ชันจับคู่กฎต้องทดสอบได้โดยไม่ต้องมี Windows และต้องมีเทสต์ที่ใช้ OCR จริงกับภาพที่สร้างในเทสต์ (เช่น วาดอีเมลด้วย Pillow) แล้วตรวจว่าเบลอคลุมตัวอักษร
