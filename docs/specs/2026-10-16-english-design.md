# StepCap — เวอร์ชันภาษาอังกฤษ (เลือกภาษา ไทย / English)

สถานะ: ร่าง รอผู้ใช้อนุมัติ · ข้อสรุปจากรอบถามตอบ 2026-10-16 · งานถัดไปคือไฟล์ติดตั้ง .exe (แยกเป็นอีกงาน)

## 1. ที่มาและเหตุผล

ผู้ใช้จะส่ง StepCap ไปติดตั้งในเครื่องคนอื่น ซึ่งบางคนไม่อ่านภาษาไทย
ตอนนี้ทุกข้อความในโปรแกรมเป็นภาษาไทย (ประมาณ 330 บรรทัดในโค้ด)

**เป้าหมาย:** คนที่ไม่อ่านภาษาไทยใช้ StepCap ได้ครบทุกอย่างเป็นภาษาอังกฤษ
และคนไทยใช้ได้เหมือนเดิม โดยใช้โปรแกรมตัวเดียวกัน

## 2. สิ่งที่ผู้ใช้ตัดสินแล้ว

- โปรแกรมเดียว เลือกภาษาในหน้าตั้งค่า (ไม่แยกเป็นสองโปรแกรม)
- ทำเวอร์ชันภาษาอังกฤษก่อน แล้วค่อยทำไฟล์ติดตั้ง .exe
- ผู้ใช้ตอบ "เริ่มได้เลย" ต่อสรุปด้านล่างทั้งหมด รวมข้อที่ผมเดา (ทำเครื่องหมาย *ผมเดา*)

## 3. พฤติกรรม

### 3.1 เลือกภาษา
- หน้าตั้งค่ามีตัวเลือก **ภาษา / Language: ไทย · English**
- เปลี่ยนแล้วมีผลทันทีทั้งโปรแกรม ไม่ต้องปิดเปิดใหม่:
  หน้าต่างหลัก, ทัวร์แนะนำ, ข้อความ toast/ข้อผิดพลาด, เมนูไอคอน tray,
  แผงลอยตอนบันทึก (แผงที่เปิดอยู่ระหว่างบันทึกเปลี่ยนตอนบันทึกครั้งถัดไปก็พอ — *การตัดสินของผม*)
- ตัวเลือกภาษาแสดงชื่อภาษาด้วยภาษาของมันเองเสมอ ("ไทย", "English") ไม่ว่าตั้งเป็นภาษาอะไร
  เพื่อให้คนที่อ่านภาษาที่ตั้งอยู่ไม่ออกยังหาทางกลับได้
- *ผมเดา:* เปิดครั้งแรกในเครื่องใหม่ (โฟลเดอร์เก็บคู่มือยังไม่มีทั้ง `settings.json` และคู่มือ)
  เลือกให้ตามภาษาหน้าจอของ Windows: ไทย → ไทย, อื่น ๆ → English แล้วจำค่านั้นไว้
- **คนที่ใช้อยู่แล้ว** (มี `settings.json` หรือคู่มืออยู่แล้วแต่ยังไม่มีค่าภาษา) ได้ภาษาไทยเหมือนเดิม
  — *การตัดสินของผม:* เครื่องที่พัฒนาอยู่นี้ Windows เป็นภาษาอังกฤษ (0x409)
  ถ้าเดาจาก Windows คนที่ใช้อยู่จะเห็นโปรแกรมกลายเป็นอังกฤษเองโดยไม่ได้ตั้ง
- ค่าภาษาเก็บใน `settings.json` key `lang` ค่า `"th"` หรือ `"en"` เท่านั้น

### 3.2 ข้อความในคู่มือ
- ข้อความที่โปรแกรมเขียนให้ตอนบันทึกใช้ภาษาที่ตั้งไว้ขณะบันทึก
  - คลิก: `Click the "Save" button in Excel` · `Right-click "Report.xlsx" in File Explorer` · `Double-click in Excel`
  - พิมพ์: `Type "hello" in the "Name" field` · `Type a password in the "Password" field` · `... then press Enter`
  - ปุ่มลัด/ปุ่มพิเศษ: `Press Ctrl+C` · `Press Left arrow`
  - ชื่อคู่มือเริ่มต้นและวันที่ใช้รูปแบบอังกฤษ เช่น `16 Oct 2026 10:00` (ไทยยังเป็น `16 ต.ค. 2569 10:00`)
- **คู่มือที่มีอยู่แล้วไม่ถูกแปล** ข้อความคงเดิม (แปลอัตโนมัติต้องใช้ AI ซึ่งไม่ใช้)
- ข้อความแจ้งที่ฝังในคู่มือ (เช่น หมายเหตุว่าซ่อนข้อมูลไม่สำเร็จ) ใช้ภาษาขณะที่เกิดเหตุ

### 3.3 ตอนส่งออก
- *ผมเดา:* ข้อความที่โปรแกรมใส่ในไฟล์ใช้ **ภาษาของโปรแกรมตอนกดส่งออก**
  ทุกรูปแบบ (Word, PDF, HTML, Markdown): "Step 1", "Contents", "12 steps",
  "Created 16 Oct 2026", "Last edited …", ชื่อไฟล์ภาพที่บันทึกแยก (`<title> - Step 3.png`)
- เนื้อหาที่ผู้ใช้เขียนไม่เปลี่ยน — คู่มือไทยที่ส่งออกตอนเป็น English ได้หัวข้อ "Step 1" แต่เนื้อหาไทย
- ไฟล์ Word: ภาษาของเอกสารเป็น en-US ตอนเป็น English (คงตั้งค่าภาษาไทยไว้สำหรับตัวอักษรไทยเพื่อให้ตัดคำ/สะกดถูก)
- HTML/PDF: `<html lang>` ตรงกับภาษาที่ส่งออก

### 3.4 Page (รวมหลายคู่มือ)
- คำว่า "Page" ใช้เหมือนกันทั้งสองภาษา
- ข้อความที่โปรแกรมสร้าง: `3 guides`, `This guide was deleted`, `<guide> Step 2`

### 3.5 คู่มือตัวอย่าง
- มีฉบับภาษาอังกฤษ **"Sample: Getting started with StepCap"** เนื้อหาเทียบเท่าฉบับไทย
  ภาพเป็นหน้าจอ StepCap ภาษาอังกฤษพร้อมคู่มือปลอมภาษาอังกฤษ (เช่น "Leave request system")
- เก็บใน repo คู่กับฉบับไทย สร้างใหม่ได้ด้วยสคริปต์ตัวเดียวกัน (เลือกภาษาได้)
- เปิดครั้งแรก: เพิ่มฉบับตามภาษาที่เลือกไว้ (ข้อ 3.1) — ยังเพิ่มครั้งเดียวเหมือนเดิม
- ปุ่ม "เพิ่มคู่มือตัวอย่าง" ในตั้งค่า เพิ่มฉบับตามภาษาตอนกด
- ทัวร์หน้าแรกจุดที่ 2 ชี้คู่มือตัวอย่างได้ทั้งสองฉบับ

### 3.6 ข้อความที่ไม่แปล
- ชื่อโปรแกรมและชื่อที่มาจากเครื่องผู้ใช้ (ชื่อปุ่ม/หน้าต่างที่จับได้, ชื่อไฟล์, ชื่อคู่มือ)
- `Ctrl+Alt+R`, ชื่อปุ่มคีย์บอร์ด (Enter, Tab, F1)

## 4. ทำอย่างไร (ส่วนที่ผมตัดสิน)

- **ตารางคำแปลไฟล์เดียว** `ui/en.json` — key คือข้อความไทยเดิม value คือภาษาอังกฤษ
  - โค้ดยังเขียนข้อความไทยเหมือนเดิม แค่ห่อด้วยฟังก์ชันแปล (`t("หยุดบันทึก")`)
    อ่านโค้ดง่ายเหมือนเดิม และตารางนี้คือรายการที่ผู้ใช้ตรวจคำแปลได้โดยตรง
  - ข้อความที่มีตัวแปรใช้ช่องแทนที่ เช่น `"{n} ขั้นตอน": "{n} steps"`
  - ข้อความไทยเดียวกันที่ภาษาอังกฤษต่างกันตามบริบท ใช้ key แยกที่มีบริบทต่อท้าย
  - ทั้งฝั่ง Python และหน้าเว็บอ่านตารางเดียวกัน
- ประโยคที่ลำดับคำต่างกันระหว่างสองภาษา (ข้อความขั้นตอนตอนบันทึก, วันที่) เขียนเป็นฟังก์ชันแยกต่อภาษา ไม่ฝืนใช้ตาราง
- **ภาษาไทยคือค่าตั้งต้นของโค้ด:** key ที่หาไม่เจอในตาราง แสดงเป็นไทย (ไม่พัง)
- เลือกภาษาครั้งแรกจากภาษาหน้าจอ Windows (`GetUserDefaultUILanguage`, primary language Thai = ไทย)

## 5. ทดสอบ

- ชุดทดสอบเดิมทั้งหมดตรึงภาษาเป็นไทย ผลไม่ขึ้นกับภาษาของ Windows เครื่องที่รัน
- **ไม่มีคำแปลหาย:** ทดสอบที่สแกนโค้ดหา `t("…")` ทุกจุด แล้วตรวจว่ามีใน `ui/en.json`
  และทุก key ในตารางยังถูกใช้อยู่
- **ไม่มีภาษาไทยหลุด:** ตั้งเป็น English แล้วเปิดทุกหน้า (หน้าแรก, รายการ, Page, ถังขยะ, ตั้งค่า,
  ดู/แก้คู่มือ, ตัวแก้ภาพ, ทัวร์, เมนูส่งออก, กล่องยืนยัน) ด้วยข้อมูลทดสอบภาษาอังกฤษ
  ต้องไม่เจอตัวอักษรไทยในหน้าจอ (ยกเว้นตัวเลือก "ไทย" ในหน้าตั้งค่า)
- ข้อความขั้นตอนตอนบันทึก, วันที่, ข้อความส่งออก Word/Markdown/HTML ตรวจทั้งสองภาษา
- สลับภาษาในตั้งค่าแล้วหน้าเปลี่ยนทันที; เมนู tray อ่านภาษาปัจจุบัน
- เปิดครั้งแรก: Windows ไทย → th + ตัวอย่างไทย, อื่น ๆ → en + ตัวอย่างอังกฤษ;
  โฟลเดอร์ที่มีคู่มือหรือ `settings.json` อยู่แล้ว (ไม่มี `lang`) → th เสมอ
- ไม่คลิก/พิมพ์บนเดสก์ท็อปจริง ใช้ `STEPCAP_STORAGE` ชี้โฟลเดอร์ชั่วคราว

## 6. ไม่ทำ (non-goals)

- แปลคู่มือที่มีอยู่แล้ว หรือแปลข้อความที่ผู้ใช้เขียน
- ภาษาที่สามหรือระบบเพิ่มภาษาทั่วไป (โครงสร้างรองรับได้ แต่ไม่ทำตอนนี้)
- แปล README, DESIGN.md, เอกสารใน docs/ และข้อความในโค้ด/คอมเมนต์
- OCR ภาษาไทยสำหรับซ่อนข้อมูลอัตโนมัติ (ยังอ่านได้เฉพาะอังกฤษเหมือนเดิม)
- ไฟล์ติดตั้ง .exe — งานถัดไป

## 7. สิ่งที่ถือว่าล้มเหลวแม้จะทำงานได้

- ตั้งเป็น English แล้วยังเจอภาษาไทยที่โปรแกรมเขียนเองโผล่ขึ้นมา
- คนไทยที่ใช้อยู่เดิมเห็นอะไรเปลี่ยนไปโดยไม่ได้ตั้งค่า (ข้อความไทยต้องเหมือนเดิมทุกคำ)
- ภาษาอังกฤษที่อ่านแล้วรู้ว่าแปลตรงตัว — ใช้คำแบบที่โปรแกรมภาษาอังกฤษทั่วไปใช้
  (เช่น "Delete", "Undo", "Export", "Settings")

## 8. ให้ผู้สร้างตัดสินเอง

- วิธีส่งตารางคำแปลและค่าภาษาให้หน้าเว็บก่อนวาดหน้าแรก
- ชื่อฟังก์ชัน/ไฟล์ย่อยฝั่ง Python
- ถ้อยคำภาษาอังกฤษแต่ละคำ (ผู้ใช้ตรวจจาก `ui/en.json` ทีหลัง)
