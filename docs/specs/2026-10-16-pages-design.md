# StepCap — ส่วนที่ 5: Pages (รวมหลายคู่มือเป็นเอกสารเดียว)

สถานะ: ร่าง รอผู้ใช้อนุมัติ (2026-10-16) · ต่อจากส่วนที่ 4 (`2026-10-16-export-formats-design.md` merge แล้ว PR #2) และงานแก้ข้อบกพร่องเล็ก (PR #3)

## 1. ที่มาและเหตุผล

ส่วนนี้คือข้อสุดท้ายของแผน: รวมคู่มือหลายอันเป็นเอกสารเดียว เหมือน Pages ของ Scribe เช่น "เริ่มงานวันแรก" ที่มีคู่มือตั้งค่าอีเมล ติดตั้งโปรแกรม และเข้าระบบลา อยู่ในไฟล์เดียว ส่งให้คนอื่นได้ครั้งเดียว

ผู้ใช้ข้ามรอบคำถามและให้เริ่มเลย ทุกการตัดสินใจในเอกสารนี้เป็นของผู้ออกแบบ ดูข้อ 6

## 2. สิ่งที่มีอยู่แล้ว (ที่เกี่ยวกับส่วนนี้)

- **คู่มือ:** `<storage>/<id>/guide.json` + ภาพ, ถังขยะ `_trash/`, `library.list_guides`, `read_guide`, ประตูกันของส่วนที่ 3 (คู่มือที่กำลังซ่อนข้อมูลตอบ 409)
- **แถบข้างของหน้าหลัก (`ui/shell.js` `PAGES`):** Home, คู่มือทั้งหมด, ถังขยะ, ตั้งค่า; การ์ดคู่มือมีเมนู เปิด/เปลี่ยนชื่อ/ทำสำเนา/ส่งออก/ลบ
- **หน้าคู่มือโหมดแก้ไข:** แถบเครื่องมือลอยมีปุ่ม "เพิ่มลงหน้า · เร็วๆ นี้" ที่ยังกดไม่ได้ (เว้นไว้ให้ส่วนนี้)
- **`renderGuide(guide, root)`:** วาดคู่มือแบบโหมดดู ใช้ทั้งในโหมดดูและไฟล์ HTML/PDF ที่ส่งออก
- **ส่งออก (ส่วนที่ 4):** เมนู HTML / PDF / Markdown / Word; ภาพทุกภาพผ่าน `renderStepPng`; `exporters.build_markdown` / `build_docx` รับคู่มือหนึ่งอัน; `numbered()` นับเลขขั้นตอนโดยข้ามหมายเหตุ

## 3. เป้าหมาย

### 3.1 รายการ Pages
- แถบข้างมีเมนูใหม่ **"Pages"** (ระหว่าง "คู่มือทั้งหมด" กับ "ถังขยะ")
- หน้า Pages แสดงการ์ดของทุก Page: ชื่อ, จำนวนคู่มือข้างใน, วันที่แก้ไขล่าสุด และปุ่ม **"+ สร้าง Page"**
- เมนูของการ์ด: เปิด, เปลี่ยนชื่อ, ส่งออก, ลบ (ลบต้องถามยืนยัน และไม่ลบคู่มือที่อยู่ข้างใน)

### 3.2 หน้าตาของ Page (โหมดดู)
- ชื่อ Page, คำอธิบาย (ถ้ามี), สารบัญของหัวข้อทั้งหมด
- แต่ละ **ส่วน** เรียงตามลำดับ มีได้ 2 แบบ:
  - **คู่มือ:** หัวข้อเป็นชื่อคู่มือ ตามด้วยขั้นตอนของคู่มือนั้นทั้งหมด หน้าตาเหมือนโหมดดูของคู่มือ เลขขั้นตอนเริ่ม 1 ใหม่ในแต่ละคู่มือ
  - **ข้อความ:** หัวข้อ (ไม่ใส่ก็ได้) และย่อหน้า สำหรับคำอธิบายระหว่างคู่มือ
- Page **อ้างถึง**คู่มือ ไม่ได้คัดลอก คู่มือที่แก้ภายหลังจะเปลี่ยนใน Page ด้วย
- คู่มือที่ถูกลบ (อยู่ในถังขยะหรือลบถาวร): แสดงกล่อง "คู่มือนี้ถูกลบแล้ว" ในตำแหน่งนั้น และนำออกจาก Page ได้ด้วยปุ่มเดียว

### 3.3 แก้ไข Page
- ปุ่ม **แก้ไข** / **เสร็จสิ้น** เหมือนหน้าคู่มือ บันทึกอัตโนมัติ
- แก้ชื่อและคำอธิบายได้
- ส่วนต่างๆ: เลื่อนขึ้น/ลง, ลบออกจาก Page, แก้หัวข้อและย่อหน้าของส่วนข้อความ
- **"+ เพิ่มคู่มือ":** หน้าต่างเลือกคู่มือ มีช่องค้นหา เลือกได้หลายอันในครั้งเดียว คู่มือเดียวกันใส่ซ้ำใน Page เดียวกันไม่ได้
- **"+ เพิ่มข้อความ"**
- เปิดคู่มือจาก Page ได้ (กดชื่อคู่มือ)

### 3.4 เพิ่มจากหน้าคู่มือ
- ปุ่ม **"เพิ่มลงหน้า"** ในแถบเครื่องมือของหน้าคู่มือ (ที่เว้นไว้) ใช้ได้แล้ว: กดแล้วเลือก Page ที่มีอยู่ หรือ "สร้าง Page ใหม่" คู่มือถูกเพิ่มไว้ท้าย Page แล้วแจ้ง "เพิ่มลงใน <ชื่อ Page> แล้ว"
- ถ้าคู่มืออยู่ใน Page นั้นแล้ว แจ้งว่า "มีอยู่ใน Page นี้แล้ว"

### 3.5 ส่งออก Page
- เมนูเดียวกับคู่มือ: HTML, PDF, Markdown (.zip), Word (.docx)
- เนื้อหาตามข้อ 3.2 ทั้งหมด ภาพทุกภาพเป็นภาพที่ซ่อนข้อมูลแล้ว (กฎเดิม)
- คู่มือที่ถูกลบไม่อยู่ในไฟล์ และแจ้งตอนเสร็จว่า "ข้ามคู่มือที่ถูกลบ 1 อัน"
- ภาพที่อ่านไม่ได้แจ้งเหมือนส่วนที่ 4 โดยบอกชื่อคู่มือและเลขขั้น
- ใช้ตั้งค่าเอกสารของ Page (สารบัญ, จำนวนคู่มือ, วันที่) ไม่ใช่ของแต่ละคู่มือ

## 4. สิ่งที่ไม่ทำในรอบนี้ และสิ่งที่ห้ามเกิดขึ้น

**ไม่ทำ**
- ถังขยะของ Page (ลบแล้วหายเลย แต่คู่มือข้างในไม่หาย)
- ค้นหา Page หรือบุ๊กมาร์ก Page
- แก้ขั้นตอนของคู่มือจากในหน้า Page (เปิดคู่มือไปแก้แทน)
- ลากวางเพื่อเรียงลำดับ (ใช้ปุ่มขึ้น/ลง)
- Page ซ้อน Page, ภาพหรือไฟล์แนบที่อยู่ใน Page เอง
- แชร์ออนไลน์

**ห้ามเกิดขึ้น**
- ลบ Page แล้วคู่มือข้างในหายหรือเสีย
- พิกเซลต้นฉบับของส่วนที่ซ่อนหลุดไปในไฟล์ส่งออกของ Page
- Page เปิดหรือส่งออกคู่มือที่กำลังซ่อนข้อมูลอยู่ (ต้องรอเหมือนหน้าคู่มือ)
- คู่มือที่ถูกลบทำให้ Page เปิดไม่ได้หรือส่งออกล้ม
- Page หรือไฟล์ของ Page ไปโผล่ในรายการคู่มือ ผลค้นหา หรือถังขยะของคู่มือ
- เทสต์ไปคลิกหรือพิมพ์บนเดสก์ท็อปจริง หรือแตะข้อมูลจริงใน `Documents\StepCap`

## 5. ข้อจำกัด

- Windows 11, Python 3.14, ทำงานในเครื่องเท่านั้น, ไม่เพิ่มไลบรารีใหม่
- ข้อความใน UI เป็นภาษาไทยทั้งหมด ธีมสว่าง ทุกอย่างอยู่ในหน้าต่างโปรแกรม
- เทสต์ใช้ `STEPCAP_STORAGE` ชี้โฟลเดอร์ชั่วคราว

## 6. สิ่งที่ผู้ออกแบบตัดสินใจเอง (ผู้ใช้ไม่ได้เป็นคนเลือก)

- **เก็บเป็น `<storage>/_pages/<id>.json`** มีแค่ `{id, title, description, created, updated, settings, sections: [{type: "guide", guide: <id>} | {type: "text", title, text}]}` โฟลเดอร์ขึ้นต้นด้วย `_` จึงไม่ปนกับรายการคู่มือ (`safe_id` ไม่รับชื่อที่ขึ้นต้นด้วย `_` อยู่แล้ว)
- **อ้างถึง ไม่คัดลอก** Page จึงเล็ก และเห็นคู่มือฉบับล่าสุดเสมอ แลกกับการที่คู่มือที่ถูกลบจะหายจาก Page (มีกล่องแจ้งแทน)
- **ส่งออกโดย "ประกอบ Page เป็นเอกสารรูปแบบเดียวกับคู่มือ"** ที่มีรายการชนิดใหม่ `section` (หัวข้อของแต่ละคู่มือ/ข้อความ) คั่นระหว่างขั้นตอน และเลขขั้นตอนเริ่มใหม่หลังแต่ละ `section` ตัวส่งออกทั้ง 4 แบบของส่วนที่ 4 จึงใช้ต่อได้ แก้เพิ่มแค่ให้รู้จัก `section`
- **ไม่มีถังขยะของ Page** เพราะ Page เป็นแค่รายการลำดับ สร้างใหม่ได้ง่าย ถามยืนยันก่อนลบพอ
- **คู่มือเดียวกันอยู่ได้หลาย Page** แต่ใน Page เดียวกันได้ครั้งเดียว
- **เรียงลำดับด้วยปุ่มขึ้น/ลง** ไม่ใช่ลากวาง เพราะ Page มักมีไม่กี่ส่วน
- **ตั้งค่าเอกสารของ Page:** สารบัญเปิดไว้เป็นค่าเริ่มต้น, จำนวนคู่มือและวันที่ปิดไว้ เปลี่ยนได้จากเมนูตั้งค่าเอกสารแบบเดียวกับคู่มือ

## 7. สิ่งที่ให้ผู้สร้างตัดสินใจเอง

- API ของ Page (เส้นทาง, รูปแบบการบันทึก) ตามแบบของคู่มือ
- หน้าตาของการ์ด Page, หน้าต่างเลือกคู่มือ และปุ่มของแต่ละส่วน ให้เข้ากับธีมเดิม
- วิธีประกอบ Page เป็นเอกสารรูปแบบคู่มือ (ทำที่หน้าเว็บหรือ Python) และวิธีส่งภาพจากหลายคู่มือ ต้องไม่ทำให้เลขขั้นตอนหรือ id ของภาพชนกันข้ามคู่มือ
- เทสต์: สร้าง/แก้/ลบ Page ไม่กระทบคู่มือ, คู่มือที่ถูกลบ, เลขขั้นตอนเริ่มใหม่ต่อคู่มือ, ไฟล์ส่งออกของ Page ไม่มีพิกเซลเดิมของส่วนที่ซ่อน, Page ไม่โผล่ในรายการคู่มือ
