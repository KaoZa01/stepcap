# StepCap — ระบบแนะนำการใช้งาน (คู่มือตัวอย่าง + ทัวร์แนะนำ)

สถานะ: ผู้ใช้อนุมัติแล้ว (2026-10-16) · สร้างแล้ว รอผู้ใช้ทดสอบจริง · ต่อจากงาน QA ก่อนเผยแพร่ (PR #5) · ข้อสรุปจากรอบถามตอบ 2026-10-16

## 1. ที่มาและเหตุผล

ผู้ใช้หลักคือพนักงานทั่วไปที่เปิด StepCap ครั้งแรกโดยไม่มีใครสอน
ตอนนี้หน้าแรกมีแค่ประโยคแนะนำกับขั้นตอนสั้น 3 ข้อ (เพิ่มตอน QA)
ซึ่งไม่พอให้คนทำคู่มือแรกและส่งออกได้เอง

**เป้าหมาย:** เปิดแอปครั้งแรกแล้วทำคู่มือแรกและส่งออกได้เองโดยไม่ต้องมีคนช่วย

ผู้ใช้เลือกทำ 2 อย่างคู่กัน:
1. **คู่มือตัวอย่าง** ที่ทำด้วย StepCap เอง อยู่ในคลังตั้งแต่เปิดครั้งแรก
2. **ทัวร์แนะนำแบบดูอย่างเดียว** บนหน้าแรกและหน้าแก้ไขคู่มือ

## 2. สิ่งที่มีอยู่แล้ว (ที่เกี่ยวกับงานนี้)

- **คลังคู่มือ:** `<storage>/<id>/guide.json` + ภาพ, `library.new_id`, `list_guides`
  - คู่มือที่มี `redact_pending` จะถูกซ่อนข้อมูลอัตโนมัติตอนเปิด (`app.guide_for_page`)
- **ตั้งค่าแอป:** `settings.json`
  - `library.DEFAULT_APP_SETTINGS` / `_clean_settings` รับเฉพาะ key ที่รู้จัก
  - `app._settings_ok` คุมว่าหน้าเว็บเปลี่ยนอะไรได้บ้าง
- **หน้าแรก (`ui/shell.js` `renderHome`):** กล่อง `.intro` มีประโยคแนะนำ `INTRO` และขั้นตอน `FIRST_RUN` ที่แสดงเมื่อยังไม่มีคู่มือ
- **หน้าแก้ไขคู่มือ (`ui/guide.js` `editPage`):** ช่องข้อความ `.stext`, ปุ่ม ขึ้น/ลง/ลบ (`.sbtns`), ปุ่ม "แก้ไขภาพ" (`.ed`), แถบเครื่องมือลอย `.etb`, ปุ่มส่งออก `#exp`
- **แผงลอยตอนบันทึก:** หน้าต่าง Tk ใน `overlay.py` (`Overlay.show_panel`)
- **ม่านซ่อนข้อมูล:** `redactCover` ใน `ui/common.js`; สถานะบันทึกมาจาก `/api/status` (`recording`)
- **กติกาดีไซน์:** `DESIGN.md` (token สี, `:focus-visible`, `activatable`, `toast`)

## 3. เป้าหมาย

### 3.1 คู่มือตัวอย่าง "ตัวอย่าง: เริ่มต้นใช้ StepCap"

**ที่มาของไฟล์**
- เก็บใน repo ที่ `samples/getting-started/` ได้แก่ `guide.json`, ภาพ PNG ของแต่ละขั้น และ `app_icon.png`
- ภาพเป็นหน้าจอ StepCap จริงที่ใส่ข้อมูลปลอม (คู่มือชื่อสมมติ เช่น "ระบบลางาน") ไม่มีข้อมูลส่วนตัว
- ภาพแผงลอย (ขั้น 3–4) ถ่ายจากแผงจริงด้วย `PrintWindow` ซึ่งดึงภาพจากหน้าต่างแผงโดยตรง ไม่จับส่วนอื่นของจอ
- เมนูใน tray ไม่มีภาพ อธิบายเป็นข้อความ

**เข้าคลังอย่างไร**
- ตอนเปิดแอป ถ้า `settings.json` ยังไม่มี `sample_added: true` ให้คัดลอกโฟลเดอร์ตัวอย่างไปเป็นคู่มือใหม่
  - ใช้ id จาก `new_id`, ตั้ง `created` / `updated` เป็นเวลาปัจจุบัน และไม่มี `redact_pending`
- ตั้ง `sample_added: true` **หลังคัดลอกสำเร็จเท่านั้น**
  - คัดลอกไม่สำเร็จ (เช่น ดิสก์เต็ม) ให้ข้ามเงียบ ๆ แล้วลองใหม่ตอนเปิดครั้งหน้า
- ผู้ใช้เดิมที่มีคู่มืออยู่แล้วก็ได้คู่มือนี้ครั้งเดียว
- ลบแล้วไม่ถูกสร้างกลับมาเอง

**สถานะในคลัง**
- เป็นคู่มือธรรมดา แก้ไข ส่งออก ลบ ใส่ใน Page ได้
- ไม่มี flag พิเศษ ชื่อขึ้นต้นด้วย "ตัวอย่าง:" เพื่อให้รู้ว่าเป็นคู่มือตัวอย่าง

**เรียกกลับมา**
- หน้าตั้งค่ามีการ์ด "การแนะนำการใช้งาน" มีปุ่ม **"เพิ่มคู่มือตัวอย่างอีกครั้ง"**
- กดแล้วสร้างสำเนาใหม่ทุกครั้ง แม้ว่าอันเดิมยังอยู่ จากนั้นแจ้ง toast และเปิดคู่มือนั้นในโหมดดู

### 3.2 ทัวร์แนะนำ

**หน้าตา**
- ฉากหลังจางทั้งหน้า มีช่องเปิดรอบปุ่มที่กำลังแนะนำ
- กรอบสีน้ำเงิน `--focus` รอบปุ่มนั้น
- กล่องคำอธิบายพื้นขาว วางข้างปุ่มฝั่งที่มีที่ว่าง ในกล่องมี:
  - หัวข้อ
  - ข้อความ 1–3 บรรทัด
  - ตัวนับ เช่น "2/5"
  - ปุ่ม **ข้าม** / **ย้อนกลับ** / **ถัดไป** (จุดสุดท้ายเปลี่ยนเป็น **เสร็จสิ้น**)

**การใช้งาน**
- **ดูอย่างเดียว:** ผู้ใช้ไม่ต้องกดปุ่มจริงตาม กดที่ฉากหลังแล้วไม่มีอะไรเกิดขึ้น
- **คีย์บอร์ด:** โฟกัสอยู่ในกล่องทัวร์ Enter = ถัดไป, Esc = ข้าม, Tab วนอยู่ในกล่อง
- **ปิดทัวร์:** หน้าเดิมกลับมาใช้ได้ตามปกติ โฟกัสกลับไปที่เดิม

**ขึ้นเมื่อไร**
- ขึ้นเองครั้งแรกที่เปิดแต่ละหน้า โดยจำชื่อทัวร์ที่ดูแล้วไว้ใน `settings.json` ที่ `tours_seen: ["home", "edit"]`
- กด ข้าม, เสร็จสิ้น หรือ Esc นับว่าดูแล้ว
- **ไม่ขึ้น (เลื่อนไปครั้งหน้า) ถ้า:**
  - กำลังบันทึกอยู่
  - ม่านซ่อนข้อมูลคลุมอยู่
  - หน้าต่างกว้างน้อยกว่า 760px
  - เป้าหมายจุดแรกไม่อยู่บนหน้า
- จุดไหนที่เป้าหมายไม่อยู่บนหน้า ให้ข้ามจุดนั้น เช่น คู่มือที่ไม่มีภาพจะไม่มีปุ่มแก้ไขภาพ
- **ดูซ้ำ:** การ์ด "การแนะนำการใช้งาน" ในหน้าตั้งค่ามีปุ่ม **"แสดงคำแนะนำอีกครั้ง"**
  - กดแล้วล้าง `tours_seen` และพาไปหน้าแรก ทัวร์หน้าแรกจะขึ้นทันที ส่วนทัวร์หน้าแก้ไขจะขึ้นเมื่อเปิดหน้าแก้ไขครั้งถัดไป

**ทัวร์หน้าแรก ("home") 3 จุด**

| จุด | ชี้ที่ | หัวข้อ | ข้อความ |
|---|---|---|---|
| 1 | ปุ่ม + บันทึกใหม่ | เริ่มบันทึกที่นี่ | กดแล้วเลือกจอ แล้วกด เริ่มบันทึก หน้าต่างนี้จะย่อลง ให้ทำงานตามปกติ แล้วกด หยุดบันทึก ที่แผงมุมขวาล่าง หรือกด Ctrl+Alt+R |
| 2 | การ์ดคู่มือตัวอย่าง (ถ้ามี) | ดูตัวอย่างก่อน | เปิดคู่มือนี้เพื่อดูว่าคู่มือที่เสร็จแล้วหน้าตาเป็นอย่างไร ลองแก้หรือส่งออกได้ตามสบาย |
| 3 | เมนูข้าง | เมนูอื่น ๆ | Page ใช้รวมหลายคู่มือเป็นเอกสารเดียว ถังขยะกู้คืนได้ ตั้งค่ามีที่เก็บไฟล์และปุ่มดูคำแนะนำนี้อีกครั้ง |

**ทัวร์หน้าแก้ไขคู่มือ ("edit") 5 จุด** ชี้ที่ขั้นแรกที่มีองค์ประกอบนั้น

| จุด | ชี้ที่ | หัวข้อ | ข้อความ |
|---|---|---|---|
| 1 | ช่องข้อความของขั้นแรก | แก้ข้อความ | พิมพ์แก้คำอธิบายของแต่ละขั้นได้เลย ระบบบันทึกให้อัตโนมัติ |
| 2 | ปุ่ม ขึ้น/ลง/ลบ ของขั้นแรก | จัดลำดับ | เลื่อนขั้นขึ้นลง หรือลบขั้นที่ไม่ต้องการ |
| 3 | ปุ่ม แก้ไขภาพ ของขั้นแรกที่มีภาพ | แก้ภาพ | ใส่ลูกศร กรอบ ข้อความ เบลอข้อมูลที่ไม่ควรให้เห็น หรือครอปภาพ |
| 4 | แถบเครื่องมือด้านขวา | เครื่องมือเพิ่มเติม | เพิ่มคู่มือนี้ลง Page เปลี่ยนสีและรูปทรงของจุดคลิก และเลือกว่าจะแสดงสารบัญหรือวันที่ในเอกสาร |
| 5 | ปุ่ม ส่งออก | ส่งออก | เลือก Word, PDF, HTML หรือ Markdown ก่อนส่งให้คนอื่น ให้ตรวจภาพอีกครั้ง และส่งเฉพาะไฟล์ที่ส่งออก |

### 3.3 หน้าแรก
- เก็บประโยคแนะนำ `INTRO` ไว้
- ลบขั้นตอน `FIRST_RUN` 3 ข้อออก (ทัวร์และคู่มือตัวอย่างทำหน้าที่นี้แทน)

## 4. สิ่งที่ไม่ทำในรอบนี้ และสิ่งที่ห้ามเกิดขึ้น

**ไม่ทำ**
- ทัวร์ในตัวแก้ภาพ หน้า Page หน้าตั้งค่า และหน้าดูคู่มือ
- ทัวร์แบบบังคับให้กดปุ่มจริงตาม และทัวร์ที่ตามไปชี้ระหว่างบันทึก
- ภาพเมนู tray
- อัปเดตคู่มือตัวอย่างในเครื่องผู้ใช้เมื่อเวอร์ชันใหม่เปลี่ยนเนื้อหา (คัดลอกครั้งเดียว)
- วิดีโอหรือภาพเคลื่อนไหว

**ห้ามเกิดขึ้น**
- คู่มือตัวอย่างถูกสร้างซ้ำทุกครั้งที่เปิดแอป หรือกลับมาเองหลังผู้ใช้ลบ
- การคัดลอกคู่มือตัวอย่างที่ล้มเหลวทำให้แอปเปิดไม่ขึ้น
- ทัวร์บังปุ่มหยุดบันทึก หรือขึ้นทับม่านซ่อนข้อมูล
- ทัวร์ค้างจนใช้หน้านั้นไม่ได้ (ต้องปิดได้ด้วย Esc และปุ่ม ข้าม เสมอ)
- ภาพในคู่มือตัวอย่างมีข้อมูลส่วนตัว หน้าต่างอื่น หรือเดสก์ท็อปจริงติดมา
- เทสต์คลิกหรือพิมพ์บนเดสก์ท็อปจริง หรือแตะข้อมูลจริงใน `Documents\StepCap`

## 5. ข้อจำกัด

- Windows 11, Python 3.14, ทำงานในเครื่องเท่านั้น, ไม่เพิ่มไลบรารีใหม่
- UI ภาษาไทย ธีมสว่าง ทุกอย่างอยู่ในหน้าต่างโปรแกรม ทำตาม `DESIGN.md`
- เทสต์ใช้ `STEPCAP_STORAGE` ชี้โฟลเดอร์ชั่วคราว

## 6. รายละเอียดที่ผู้ออกแบบเลือกเอง (ผู้ใช้ยืนยันข้อสรุปรวมแล้ว)

- **API ใหม่**
  - `library.add_sample(storage, src) -> id | None`: คัดลอก + ตั้งเวลา ล้มเหลวคืน `None` ไม่ throw
  - `POST /api/sample`: เพิ่มอีกครั้ง คืน `{id}`
  - `settings.json` เพิ่ม `sample_added` (bool) กับ `tours_seen` (list ของชื่อทัวร์)
  - `_settings_ok` ให้หน้าเว็บเขียน `tours_seen` ได้ แต่เขียน `sample_added` ไม่ได้
- **จุดที่สร้างคู่มือตัวอย่าง:** `app.main()` ก่อนเปิดหน้าต่าง ทำงานคู่กับ `ensure_app_icon` และกลืนข้อผิดพลาดทุกแบบ
- **โค้ดทัวร์:** อยู่ไฟล์ใหม่ `ui/tour.js` (ฟังก์ชันเดียว `runTour(name, stops)` + ข้อมูลทัวร์ 2 ชุด) ส่วน CSS อยู่ใน `index.html` ใช้ token เดิม
- **สคริปต์สร้างคู่มือตัวอย่าง:** `samples/make_getting_started.py` อยู่ใน repo ใช้สร้างภาพใหม่เมื่อ UI เปลี่ยน
  - เปิดแอปบนโฟลเดอร์ชั่วคราว แล้วถ่ายภาพจากหน้าต่างของแอปเอง และถ่ายแผงด้วย `PrintWindow`
  - แผงจะโผล่ที่มุมจอประมาณ 1 วินาทีตอนรัน ไม่ส่งการคลิกหรือคีย์ใด ๆ
  - ภาพที่ได้ต้องตรวจด้วยตาก่อน commit
- **เทสต์**
  - `test_library`:
    - `add_sample` คัดลอกครบ ได้ id ใหม่ และไม่มี `redact_pending`
    - คัดลอกล้มเหลวแล้วคืน `None`
    - ค่า settings ใหม่ผ่าน `_clean_settings`
  - `test_render`:
    - ทัวร์หน้าแรกขึ้นครั้งแรก, Esc ปิดแล้วจำไว้, ไม่ขึ้นซ้ำ, "แสดงคำแนะนำอีกครั้ง" ทำให้ขึ้นอีก
    - ทัวร์ไม่ขึ้นเมื่อหน้าต่างแคบ
    - ทัวร์หน้าแก้ไขมี 5 จุด และข้ามจุดที่ไม่มีเป้าหมาย
    - หน้าแรกไม่มี `FIRST_RUN`
  - `test_app`:
    - เปิดแอปบนที่เก็บว่างแล้วมีคู่มือตัวอย่าง 1 อัน เปิดครั้งที่ 2 ยังมี 1 อัน
    - ลบแล้วเปิดใหม่ก็ไม่กลับมา
    - `POST /api/sample` เพิ่มได้อีก
  - คู่มือตัวอย่างใน repo: `read_guide` อ่านได้, มีขั้นตอนเลขกำกับ 7 ขั้น + หมายเหตุ 3 อัน, ทุกภาพที่อ้างถึงมีอยู่และเปิดได้
