# English Version (ไทย / English switch) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One StepCap that runs fully in Thai or fully in English, chosen in Settings, with Thai users seeing no change.

**Architecture:** Code keeps its Thai strings and wraps each in `tr("…")`. One table `ui/en.json` maps Thai → English and is read by both sides: `i18n.py` (Python, global `LANG`) and `tr()` in `ui/common.js`. The app writes `LANG`/`EN` into the page when it serves `/`. Sentences whose word order differs (recorded step text, dates) use small per-language functions instead of the table. A lint test (`test_i18n.py`) fails on any Thai outside `tr("…")` in the files it covers. Each task adds its files to that list.

**Tech Stack:** Python 3.14 stdlib + existing deps (pywebview/WebView2, Pillow, tkinter, pystray, python-docx), vanilla JS. No new libraries.

**Spec:** `docs/specs/2026-10-16-english-design.md` (approved 2026-10-16)

## Global Constraints

- Settings key `lang`: `"th"` | `"en"` only. Default `"th"`. The page may write it.
- Thai output must not change, word for word. Every existing test keeps passing unchanged, except where a constant is renamed in this plan.
- Translation function name is `tr` in both Python and JS. `t` is already a common local variable in the code.
- `tr(th, **kw)` / `tr(th, {…})`:
  - Thai returns `th`.
  - English returns `EN[th]`, falling back to `th` when the key is missing.
  - Placeholders are `{name}`. Substituted values are never re-scanned.
  - When `n == 1` and the key `th + "#1"` exists in English, that entry is used (singular).
- Every `tr()` argument is a plain string literal: no f-string, no `${}`, no variable.
- Per-language tables that cannot go through `tr` (recorder nouns and keys, month names, sample titles) sit on lines marked `i18n-ok`.
- Fresh storage, meaning no `settings.json` and no `<dir>/guide.json`:
  - `lang` is chosen from Windows and then saved.
  - Otherwise, with no `lang` key, the language is `"th"`.
  - An unreadable `settings.json` gives `"th"`, and the file is not rewritten.
- "Windows is Thai" means the UI (display) language is Thai: `GetUserDefaultUILanguage() & 0x3FF == 0x1E`. User's choice 2026-10-16: locale and code page are not counted.
- The language option labels are always `ไทย` and `English`.
- English dates:
  - title stamp `16 Oct 2026 10:00`
  - document date `16 Oct 2026`, rendered by the UI as `en-GB {day: "numeric", month: "short", year: "numeric"}`
- Word export: `w:lang` `val` is `en-US` in English and `th-TH` in Thai. `bidi` and `eastAsia` stay `th-TH`.
- "Page" stays "Page" in both languages.
- Tests never click or type on the real desktop. They use `STEPCAP_STORAGE` temp dirs and run as `.venv/Scripts/python.exe test_X.py`.

## Review Focus

1. **Upgrade on English Windows:** storage with guides but no `settings.json` stays Thai (test in Task 1).
2. **Corrupt `settings.json` at launch:** language is Thai, and the file is byte-for-byte untouched (test in Task 1).
3. **User text containing `{n}` or `$&`:** a value put into a template comes out literally, in both Python and JS (tests in Task 1).
4. **Counts of exactly 1:** "1 step", "1 guide", "1 min ago". Every English key with `{n}` has a `#1` twin (lint test in Task 1, applied as the table grows).
5. **Page export in English with a GIF in a section:** the server's failed-step labels and the page's labels match, so they sort (test in Task 5).
