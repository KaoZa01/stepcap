# ส่วนที่ 5 Pages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pages: documents that combine several guides (plus text blocks) in order, with list/create/edit/delete, "add to page" from a guide, a view mode and the four export formats.

**Architecture:** A page is a small JSON in `<storage>/_pages/<id>.json` that references guides by id. To show or export it, the server compiles it into one guide-shaped document (`library.compile_page`) whose `steps` hold new `kind: "section"` entries between each guide's steps (step ids prefixed with the guide id, each carrying `gid`). `renderGuide` and the piece-4 exporters learn `section` (heading + optional body, numbering restarts) and a `meta` override; everything else is reused.

**Tech Stack:** Python 3.14 stdlib, existing pywebview page JS, piece-4 `exporters.py`. No new dependencies.

**Spec:** `docs/specs/2026-10-16-pages-design.md`

## Global Constraints

- Pages live only under `<storage>/_pages/`; they never appear in guide lists, search or guide trash. Deleting a page never touches a guide.
- A page references guides; nothing is copied. A trashed/purged guide shows as "คู่มือนี้ถูกลบแล้ว" and is skipped in exports with `"ข้ามคู่มือที่ถูกลบ N อัน"`.
- The piece-3 gate holds: compiling a page whose guide is being redacted answers 409; a `redact_pending` guide is checked first (use `app.guide_for_page`, never `read_guide` directly, when compiling in the app).
- Export pictures only via `renderStepPng`; no original pixels of hidden areas.
- Page default settings: `{"toc": true, "step_count": false, "created": false, "updated": false}`; meta for a page counts guides: `"<n> คู่มือ"`.
- All UI copy Thai; tests on temp `STEPCAP_STORAGE`, no real desktop input. Run each as `.venv/Scripts/python.exe test_X.py`.

## Review Focus

- A guide trashed after being added → page still opens, shows the placeholder, export skips it and says so. Pinned in Task 1 (`test_compile_skips_missing`) and Task 4 (`test_page_view_missing_guide`).
- The same guide added twice → refused with "exists". Pinned in Task 1 (`test_add_guide_once`).
- Two guides with the same step ids (duplicated guide) in one page → no id/image collisions in compile and exports. Pinned in Task 1 (`test_compile_ids_unique`) and Task 2 (`test_md_sections_images_unique`).
- Step numbering restarts at 1 for each guide in view and all exports. Pinned in Task 2 (`test_numbered_restarts_after_section`) and Task 4 (`test_page_view_numbering`).
- A hand-broken `_pages/x.json` → ignored in the list, 404 on open, never crashes the Pages screen. Pinned in Task 1 (`test_list_pages_skips_bad`).

### Task 1: Page storage and compile (`library.py`)

**Files:** Modify `library.py`; Test `test_library.py`

**Interfaces — Produces:**
- `PAGES_DIR = "_pages"`, `DEFAULT_PAGE_SETTINGS` (values above).
- `create_page(storage, title: str) -> dict` — id from `new_id`-style timestamp (`"p" + new_id(...)` is fine; must pass `safe_name`), `description: ""`, `sections: []`, created/updated `now_iso()`.
- `read_page(storage, pid) -> dict | None` (normalized: missing keys get defaults; invalid → None), `save_page(storage, pid, data) -> bool` (validates with `_is_page`, keeps `id`, sets `updated`), `delete_page(storage, pid) -> bool`, `list_pages(storage) -> list[dict]` — `{id, title, count, updated, ago}` newest `updated` first.
- `_is_page(d) -> bool` — `title`/`description` str, `settings` dict, `sections` list of `{"type": "guide", "guide": <safe_id str>}` or `{"type": "text", "title": str, "text": str}`.
- `add_guide_to_page(storage, pid, gid) -> str | None` — `"added"`, `"exists"`, or `None` (no such page/guide).
- `compile_page(page: dict, guides: dict[str, dict | None]) -> tuple[dict, int]` — pure. Returns (`doc`, `missing_count`). `doc` = `{"id": page id, "title", "created", "updated", "settings": {**page settings, "step_count": False}, "meta": "<n> คู่มือ" if page settings step_count else absent, "steps": [...]}`. Per guide section: `{"id": "sec<i>", "kind": "section", "text": guide title, "gid": gid}` then each guide step copied with `id = f"{gid}.{sid}"` and `gid = gid`. Per text section: `{"id": "sec<i>", "kind": "section", "text": title, "body": text}`. A guide mapped to `None` contributes `{"id": "sec<i>", "kind": "section", "text": "คู่มือนี้ถูกลบแล้ว", "missing": True, "gid": gid}` and counts in `missing_count`.

### Task 3: Page routes (`app.py`)

**Files:** Modify `app.py`; Test `test_app.py`, `test_redact.py` (in-process gate test, same `_app()` pattern)

**Interfaces — Produces:**
- `GET /api/pages` → `list_pages`. `POST /api/pages` `{title}` → created page.
- `GET /api/page/<pid>` → page JSON + `"guides": {gid: {"title": str} | None}` for its guide sections (None = deleted). `GET /api/page/<pid>/doc` → compiled doc (+ `"missing": n`), 409 while any of its guides is in `REDACT_BUSY`.
- `POST /api/page/<pid>` save (400 on invalid), `/delete`, `/add` `{guide}` → `{"result": "added"|"exists"}` (404 if None), `/export?format=…` — same bodies and replies as the guide export; the server compiles the page for md/docx and passes the compiled doc to `_export_images` (which must read each GIF from `STORAGE / step["gid"]`), reply adds `"skipped": n` for missing guides.
- `page_doc(pid) -> dict | int` — compiles via `guide_for_page(gid)` per guide section (409 propagates; 404 → None).
- `pid` must pass `library.safe_name`; path stays inside `_pages`.
